# 컨텍스트 정리 설계서 — 다목적 작업장 재정의

## 1. 문제 진단

이 프로젝트는 ① LLM 기반 분석 작업 위주로 시작 → ② LLM 자동 생성 파이프라인 구축 후
폐기 → ③ 창작자 직접 집필 + 에이전트 보조로 전환된 이력이 있다. 그 과정에서
폐기된 분석/파이프라인 시대의 전제가 살아있는 컨텍스트 문서에 잔류해, 창작자가
구상·기획·분석·집필·디자인 등 성격이 다른 작업을 할 때마다 불필요한 형식·내용을
강제당하는 문제가 발생했다.

### 진단으로 확정된 사실

- **lore의 살아있는 두 문서(세계관_설정 v0.10, 사상체_정의 v0.8)는 이미 정리 완료.**
  frontmatter 참고 문서에 방법론이 없고, "방법론" 단어는 갱신 로그의 "제거했다" 기록에만
  존재(= 역사 기록, 불변 대상). → **lore는 변경 없음.**
- **archive/는 살아있는 문서가 참조하지 않음.** → **archive는 손대지 않음.**
- **실제 잔재가 남은 살아있는 문서는 2개:** `AGENTS.md`, `planning/프로젝트_의도_v1.7.md`.

## 2. 설계 원칙 (사용자 확정)

1. **기본값 = 형식 강제 없음.** 작업 성격은 그때그때 다르며, 어떤 형식도 모든 작업에
   기본 강제되지 않는다.
2. **엄격한 작업유형 분류를 만들지 않는다.** "5작업유형 + 유형별 규칙"은 옛 "5항목 강제"의
   재판이다. 작업 유형은 칸막이가 아니라 느슨한 참조 안내일 뿐.
3. **방법론은 선택적 자료로 강등.** 가치는 있으나 항상 필요하진 않다. 어떤 라우팅·지침도
   "항상 읽어라"고 가리키지 않으며, 창작자가 필요하다 판단해 명시적으로 지시할 때만 읽는다.
   파일 자체는 삭제하지 않는다.

## 3. 변경 명세

### 대상 A — `AGENTS.md`

A-1. **도입부 정체성 재정의 (3행).** "세계관 설계, 사상체 문서 작성, APMB 웹사이트 개발이
     주된 작업이다."를, 프로젝트가 구상·기획·분석·집필·디자인 등 성격이 다른 작업을 상황에
     맞게 진행하는 **다목적 작업장**이며, **작업 성격에 따라 필요한 문서만 참조하고 어떤
     형식도 모든 작업에 기본 강제되지 않는다**는 태도를 담아 보강한다.

A-2. **§5 "방법론 내부 도구는 노출하지 않는다" 원칙 삭제 (55–56행).** 이 원칙은 모든 작업에
     방법론이 배경 작동한다는 전제를 깔고 있다. 삭제하고, 뒤따르는 §6의 번호를 §5로 당긴다.

A-3. **폴더 구조 주석 수정 (113행).** "patterns/ — 방법론 문서 (LLM 내부 도구)"를
     "방법론 문서 (선택적 장르 분석 자료)"로 교체. 항상 쓰는 내부 도구가 아니라 선택 참조임을
     반영.

A-4. **(유지) 명명 규칙의 방법론 항목 (129행).** 파일이 실제로 `방법론_*.md`로 명명되어
     있으므로 명명 규칙 자체는 사실이다. 유지한다.

A-5. **(유지) §1 세부 참조의 `작업_방식` 항목 (25행).** 이미 존재하고 올바르다. 유지.

### 대상 B — `planning/프로젝트_의도_v1.7.md` → v1.8

B-1. **§0.1 라우팅 표의 `방법론_*_분석` 행 수정 (46행).** "참조 시점: 사상체 구상·창작 시
     장르 이해를 위한 참고 (LLM 내부 참조, 사용자에게 해설할 대상 아님)"를
     **"창작자가 필요하다 판단해 명시적으로 지시할 때만 참조하는 선택적 장르 분석 자료. 어떤
     작업에도 기본 참조로 강제되지 않음"**으로 교체.

B-2. **§0.1 라우팅 표에 `작업_방식` 행 추가.** 현재 표에 누락. "사상체 문서·작품의 집필 동선과
     창작자–에이전트 역할 분담 / 참조 시점: 사상체 문서를 직접 집필·정리할 때" 취지로 1행 추가.

B-3. **버전 v1.7 → v1.8.** frontmatter 버전·최종 갱신일(2026-06-13) 갱신, v1.7→v1.8 변경 로그
     1줄 추가. 새 파일 `프로젝트_의도_v1.8.md` 생성, 구 파일 `프로젝트_의도_v1.7.md`는
     `planning/archive/`로 이동.

## 4. 명시적 비-변경 (안전벽)

- `patterns/방법론_*.md` 파일 — 삭제 안 함, 내용 안 건드림. 위상만 "선택적"으로.
- `lore/` 두 문서 — 변경 없음. 갱신 로그의 "방법론 제거" 기록은 역사 기록이므로 불변.
- `archive/` 전체 — 손대지 않음.
- `docs/working/` 파일·폴더명 — 손대지 않음.
- 세계관·사상체 *내용*(노스포비아 본체, 식별코드, 표면/본질 구조 등) — 절대 불변.

## 5. 실행·검증 방식

1. **Sonnet 워크플로** — A(AGENTS.md)와 B(프로젝트_의도)는 독립적이라 병렬 편집.
2. **Opus 검증** — (a) 방법론 강제 제거 누락 없음, (b) 비-변경 안전벽 준수(세계관 내용·archive·
   lore 불변), (c) 문서 간 정합(라우팅·버전·교차참조) 확인.
3. **커밋** — 의미 단위. 예: "컨텍스트 정리: 다목적 작업장 재정의 + 방법론 선택참조 강등".
