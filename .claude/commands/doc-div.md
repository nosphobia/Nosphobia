# /doc-div — 사상체 문서 분해

## 인자

- `$1` *(필수)* — 분해할 사상체 문서 경로 (예: `@docs/entities/사상체_노스포비아_v0.6.md`)

## 사용 모델

**없음** — 순수 프로그램 도구(`infra/tools/scripts/decompose.ts`) 호출만 수행. LLM의 해석·창작 불필요.

## 실행 흐름

LLM은 다음을 순차 실행한다.

1. **입력 검증**
   - `$1`이 제공되었는지 확인. 미제공 시 사용자에게 사상체 문서 경로를 요청.
   - 해당 경로가 존재하는지 확인. 없으면 사용자에게 정확한 경로 안내.
   - frontmatter의 `식별코드`를 읽어 순서코드(예: `Aj-06-SP-0341`의 `0341`)를 추출.
   - `docs/working/<순서코드>/`가 이미 존재하면 중단. 사용자에게 알림.

2. **프로그램 도구 호출**
   - `infra/tools/scripts/decompose.ts`를 실행 (호출 형식은 도구 구현 시점에 확정).
   - 도구는 다음을 수행:
     - 사상체 문서를 헤더 단위로 5개 영역 분리 (`## 개요`, `## 변칙 현상`, `## 격리 절차`, `## 대응 지침`, `## 사건 기록`)
     - frontmatter는 `<순서코드>_개요.md`의 머리에 보존
     - `<순서코드>_개요.md` 안에 `## 개요` 영역 전체(표 + `### 파생 개체` + `### 설명`) 저장
     - 빈 피드백 파일 5개 생성
     - 원본 문서를 `docs/entities/archive/`로 이동

3. **결과 보고**
   - 사용자에게 `docs/working/<순서코드>/` 폴더가 생성되었음을 알림.
   - 다음 단계 안내: 피드백 파일에 수정 사항 작성 후 `/doc-review <순서코드>` 호출.

## 산출물

`docs/working/<순서코드>/` 폴더에 10개 파일 (`/doc-init`과 동일한 구조).

## 예외 처리

- **decompose.ts가 미구현 상태**: 도구 구현 전까지는 *수동 분해*가 필요함을 사용자에게 알리고, 본 명령어는 *기획만 정의된 상태*임을 명시.
- **원본 문서의 헤더 구조가 표준과 다름**: 도구 실행 결과를 사용자에게 보고하고 사용자가 수동 정정 후 재시도하도록 안내.
- **순서코드 추출 실패** (frontmatter에 식별코드 없음 등): 처리 중단. 사용자에게 식별코드 필드를 frontmatter에 추가하도록 안내.
