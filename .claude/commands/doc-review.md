# /doc-review — 사상체 피드백 적용

## 인자

- `$1` *(필수)* — 4자리 순서코드 (예: `0341`)

## 사용 모델

**현재 모델** — 사용자가 `/model`로 사전 선택한 모델 사용. 시스템은 피드백 태그를 보고 자동으로 모델을 변경하지 않는다.

권장 모델 선택 가이드:
- 피드백이 주로 `[창작]` 태그 → Opus 권장
- 피드백이 주로 `[정합]` 태그 → Sonnet 권장
- 혼합 → 사용자 판단

## 실행 흐름

LLM은 다음을 순차 실행한다.

### 1. 입력 검증

- `$1`이 4자리 숫자인지 확인. 형식 오류 시 사용자에게 안내.
- `docs/working/<순서코드>/` 폴더가 존재하는지 확인. 없으면 중단.
- 5개 피드백 파일(`<순서코드>_<항목>_fb.md`)이 모두 존재하는지 확인.

### 2. 피드백 수집

각 피드백 파일에서 *처리 대기* 영역의 `- [ ]` 항목을 수집:

- 5개 파일 모두 검사
- 비어있는 처리 대기 영역은 *스킵* (해당 항목은 갱신 불요)
- 각 피드백 항목의 *태그*(`[창작]` / `[정합]`)와 *내용*을 파싱

### 3. 피드백 적용

각 피드백에 대해 *대응되는 항목 파일*을 갱신:

| 피드백 파일 | 갱신 대상 항목 파일 |
|---|---|
| `<순서코드>_개요_fb.md` | `<순서코드>_개요.md` |
| `<순서코드>_변칙현상_fb.md` | `<순서코드>_변칙현상.md` |
| `<순서코드>_격리절차_fb.md` | `<순서코드>_격리절차.md` |
| `<순서코드>_대응지침_fb.md` | `<순서코드>_대응지침.md` |
| `<순서코드>_사건기록_fb.md` | `<순서코드>_사건기록.md` |

**갱신 시 주의 사항**:
- 사상체 정의(`lore/사상체_정의_*.md`)의 §6.4 인용 표기, §6.5 문체, §7 톤·미학 가이드를 준수.
- 표면/본질 이중 구조 유지.
- 검열 비율 5~15% 유지 (§7.2).
- `[창작]` 태그는 *해석·재창작* 여지를 가지고 처리. 사용자의 *의도*를 추론하여 본문 변경.
- `[정합]` 태그는 *명시적 변환*. 지시 그대로 적용.

### 4. 피드백 마킹

처리된 피드백은 다음 변경을 받는다:

1. 체크박스 `- [ ]` → `- [x]`
2. *처리 대기* 영역에서 *처리 완료* 영역으로 이동
3. 항목 끝에 ` — 처리일: YYYY-MM-DD` 추가 (오늘 날짜)

처리 실패한 피드백(예: 의도가 모호하여 적용 불가)은 *처리 대기* 영역에 그대로 두고, 항목 뒤에 ` — [재확인 필요] 사유` 주석을 추가.

### 5. 결과 보고

사용자에게 다음을 보고:

- 처리 완료된 피드백 수 (항목별)
- 처리 실패한 피드백 수와 사유
- 갱신된 항목 파일 목록
- 다음 단계 안내: 추가 피드백 필요 시 피드백 파일에 작성 후 재호출. 완료 시 `/doc-ig <순서코드>` 호출.

## 예외 처리

- **모든 피드백 파일의 처리 대기 영역이 비어있음**: 사용자에게 *처리할 피드백 없음* 보고 후 종료. 다음 단계로 `/doc-ig` 안내.
- **피드백 파일 형식 오류** (표준 영역 헤더 누락 등): 해당 파일의 피드백은 처리 보류. 사용자에게 형식 정정 요청.
- **항목 파일이 존재하지 않음**: 처리 중단. `docs/working/` 폴더 무결성 확인 요청.
