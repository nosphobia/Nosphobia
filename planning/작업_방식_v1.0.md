# 작업 방식

이 문서는 노스포비아 프로젝트에서 *사상체 문서와 그 안의 작품(대응 지침·사건 기록·격리 절차)을 어떻게 만들어가는가*의 작업 동선과 역할 분담을 정의한다.

## 본 문서가 다루는 영역

- 창작자와 에이전트(LLM)의 *역할 분담*
- 작품이 쌓이고 흐르는 *폴더 동선* (씨앗 → 집필 → 확정)
- 작업의 *2단계 진화* (Phase A 집필기 → Phase B 분석·도구화기)

## 본 문서가 다루지 않는 영역 (별도 문서 참조)

- 사상체 문서의 *형식·표기·문체* — `사상체_정의.md`
- 세 작품이 *옴니버스 단편이라는 성격*과 상호 관계 — `사상체_정의.md` §6.2.0, `프로젝트_의도.md` §2.4
- 작품을 시청자에게 *어떻게 노출·유통하는가* — `프로젝트_의도.md` §4 (APMB 웹사이트가 사상체 문서마다 페이지를 두어 일람·노출)

---

## 1. 두 단계(Phase) 구조

이 작업 방식은 두 단계로 진화한다.

| 단계 | 시기 | 핵심 |
|---|---|---|
| **Phase A — 직접 집필기** | 지금 ~ 당분간 | 창작자가 직접 쓰고, 에이전트가 보조한다. 작품을 *쌓는다*. |
| **Phase B — 분석·도구화기** | 창작자가 준비됐다고 판단할 때 | 쌓인 창작자의 작품을 분석해 *창작자 전용 패턴*을 도구화한다. |

Phase A가 현재 운용되는 단계이며, 본 문서의 §2~§3이 Phase A를 정의한다. Phase B는 §4에 *예정*으로만 명시한다.

---

## 2. Phase A — 역할 분담

### 2.1. 펜은 창작자가 잡는다

사상체 문서·작품의 초안과 본문은 **창작자가 직접 집필**한다. 모든 창작 결정의 주인은 창작자다. 에이전트는 글을 대신 쓰지 않는다.

| 주체 | 역할 |
|---|---|
| **창작자** | 초안·본문 직접 집필. 모든 창작 결정. |
| **에이전트** | ① 아이디어 제안 ② 문체·연출 분석/제안 ③ 초안 검토·정합 점검 ④ 파일 정리·커밋·다중문서 정합 |

### 2.2. 대화 흐름

작업은 *대화로 직접 주고받는* 흐름이다. 별도의 피드백 파일이나 슬래시 명령어 기반 처리 루프는 없다. 에이전트의 도움이 필요한 지점에서 창작자가 그때그때 요청한다.

- **아이디어가 필요할 때** — 새 사상체 콘셉, 변칙성 양상, 수칙·사건 아이디어 등을 제안받는다. 결정은 창작자가 한다.
- **문체·연출 제안이 필요할 때** — 구체적 문체·연출을 제안받는다.
- **초안 검토가 필요할 때** — 작성한 글을 에이전트가 읽고 표면/본질 이중 구조·모호함의 균형·설정 정합성·표기 규칙(`사상체_정의.md`)을 점검한다.
- **파일을 정리할 때** — 완성·확정된 글을 적절한 위치로 옮기고, 명명·버전·커밋·다중문서 정합을 에이전트가 처리한다.

### 2.3. 에이전트가 자동으로 하지 않는 것

폐기된 doc 파이프라인과 달리, 다음은 *자동으로 일어나지 않는다*:

- 사상체 문서를 5항목으로 자동 분해하거나 자동 통합하는 일
- 정합성을 자동 검증해 통과/실패를 가르는 일
- 작업 공간(`working/`)을 확정 영역(`entities/`)으로 자동 이동하는 일

이 동선의 이행은 창작자의 판단으로 일어나며, 그때 에이전트가 파일 작업을 돕는다.

---

## 3. Phase A — 작업 동선

작품은 *씨앗 → 집필 → 확정*의 세 단계로 흐르고, 각 단계가 폴더에 대응한다.

```
[1] 씨앗·원자재        docs/raw/
     │                 콘셉·소재·레퍼런스 메모. 형식 제약 없음.
     ↓
[2] 집필 (작업 중)     docs/working/<순서코드>_<사상체명칭>/
     │                 예: docs/working/0341_노스포비아/
     │                 창작자가 직접 집필. 폴더 안 파일 구성은 자유.
     ↓
[3] 확정 (완성작)      docs/entities/사상체_<이름>_v<버전>.md
                       완성된 한 편. 구버전은 entities/archive/로.
```

### 3.1. 씨앗 — `docs/raw/`

사상체 콘셉·소재·레퍼런스를 자유롭게 서술하는 원자재 공간. 형식 제약이 없다. 발상 단계의 브레인스토밍 메모도 여기에 둔다.

### 3.2. 집필 — `docs/working/<순서코드>_<사상체명칭>/`

창작자가 직접 집필하는 작업 공간. 사상체 한 편이 하나의 폴더에 대응한다.

- **폴더명 = `<순서코드>_<사상체명칭>`** (예: `0341_노스포비아`). 순서코드는 식별코드와 연결되고, 명칭은 사람이 폴더명만 봐도 어느 사상체인지 알게 한다. 여러 사상체를 동시에 작업해도 섞이지 않는다.
- **폴더 안 파일 구성은 자유.** 5항목 분해(개요·변칙현상·격리절차·대응지침·사건기록 파일)는 *강제되지 않는다*. 한 파일에 다 쓰든, 작품별로 쪼개든 창작자의 선택이다.
- **단, frontmatter는 일관되게 유지한다.** 사상체 명칭·식별코드·버전 등 메타데이터를 일관되게 두면, Phase B에서 작품들을 분석할 때 실마리가 된다(§4).

### 3.3. 확정 — `docs/entities/`

완성된 사상체 문서가 모이는 곳. *피드백을 받기 위한 것이 아니라 읽히기 위한* 영역이다.

- 파일명: `사상체_<이름>_v<버전>.md` (명명 규칙은 `프로젝트_의도.md` 라우팅 및 AGENTS.md 참조)
- 구버전은 `docs/entities/archive/`로 이동.
- **이 폴더가 Phase B의 분석 대상 풀이 된다.** 완성작이 흩어지지 않고 한곳에 쌓이는 것이 중요하다.

---

## 4. Phase B — 분석·도구화기 (예정)

> 🚧 본 절은 *예정*이며, 구체적 방법은 Phase B 진입 시 설계한다.

Phase A에서 창작자의 작품이 충분히 쌓이면, 그 작품들을 분석해 **창작자 고유의 패턴**을 추출하고 도구화한다.

- **목적**: 창작자의 줄거리·콘셉·설정·플롯(*소설 용어로서의 플롯* — 이야기를 실제로 풀어내는 서사 구조) 패턴을 학습해, 신작 작업 시 *구조 제안*을 받아 생산성을 높인다.
- **폐기된 생산 파이프라인과의 차이**: 폐기된 방식은 *외부 레퍼런스(수색연합·처리반 등)를 분석한 일반론*이었다. Phase B는 *창작자 자신의 작품을 학습한 창작자 전용 보조*다. 남의 옷이 아니라 창작자 몸에 맞춘 옷이다.

### 진입 트리거

**창작자가 "준비됐다"고 판단할 때.** 작품 수의 고정 기준은 두지 않는다. 창작자가 호출하면 그 시점에 분석 방법(무엇을 입력으로, 어떤 패턴을 어떤 형태로 추출할지)을 함께 설계한다.
