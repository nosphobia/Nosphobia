큰 기획적 결정이 바뀔 때만 본 문서를 갱신한다.

## 1. 웹사이트의 정체와 핵심 전략

### 1.1. 정체

- *컨셉상 표면*: 초상현상관리국 직원이 사용하는 내부 인트라넷
- *실제 사용자*: IG 등급으로 임시 인가된 외부 탐사자(시청자)
- *주된 타겟 관객*: 데뷔 전 홍보로 유입된 호기심형 마이너 장르 팬

### 1.2. 핵심 전략

> *데뷔 시점 사이트의 무게중심 90%는 관리국 내부 자료. 사상체 자료는 노스포비아 1편만 정식 등재, 나머지는 의도적인 빈 자리(접근 불가)로 둔다. 호기심 유입자가 "진짜 정부 인트라넷에 들어왔다"고 느끼게 만드는 것이 1순위 목표.*

이유:
- 관리국은 사상체보다 더 큰 무대다. 무대가 정교하면 단 한 명의 배우(노스포비아)만 등장해도 무게가 실린다.
- 마이너 장르 팬은 *세계관의 깊이*에 반응한다. 사상체 개수가 아니라 *제도적 디테일*이 진짜 정부 같다는 인상을 만든다.
- 빈 자리(접근 불가)는 *부족*이 아니라 *의도된 떡밥*이 된다. 적게 만들수록 빈 자리가 미스터리가 된다.

### 1.3. 디자인 키워드

- 2000년대 정부 인트라넷, 관료주의적, 형식적, 건조하고 불길한 톤
- 포인트 컬러: `#322659` (남보라, 노스의 상징색)

## 3. 검열 기준

본 사이트의 검열은 **IG 등급 사용자가 열람 권한이 없는 정보**를 기준으로 한다. 컨셉상 다른 보안 등급들이 존재하지만, 실 사용자가 IG 등급뿐이므로 검열은 IG 단일 기준으로 단순화한다.

검열 표기:
- `█` (검은 박스): 의미를 특정할 수 있는 단어/이름/숫자 단위
- `[데이터 말소]`: 텍스트 블록 단위
- `[기밀 분류]`: 사용자의 등급 미달
- `[기록 보류]`: 사건 진행 중 또는 결론 미확정
- 검열 길이는 원문 길이와 비례 — 가린다는 사실 자체가 "여기에 무엇이 있다"는 정보가 됨

(검열 표기 규약의 상세는 페이지 3-3에서 다룸)

## 4. 톤 전략 — 호러 연출 매트릭스

호러 연출 = 페이지 표면에 호러 장르 요소가 얼마나 노골적으로 드러나는가. 페이지 종류에 따라 다르게 배치한다.

| 페이지 종류 | 호러 연출 | 이유 |
|---|---|---|
| 인트로 / 접속 게이트 | 중간-높음 | 첫인상이 분위기를 결정. 부팅·로그·인가 확인 연출 |
| **로그인 / 회원가입 페이지 (통합)** | 거의 0% | *IG 등급 인가 확인*·*임시 인가 신청*의 행정 양식. 모드 토글이 같은 컨테이너 안에서 즉시 전환되는 *건조한 정부 폼* 톤 |
| **보안 서약서** | 중간 | 인-유니버스 법조항·규약의 *어휘 자체*가 균열의 자리. 시각적 호러 효과는 절제 |
| 메인 대시보드 | 낮음 (가끔 균열) | 일상감 유지. 단 *최근 사건* 항목에 가끔 이상한 게 노출 |
| 기관 안내·조직 구조 | 거의 0% | 신뢰감 우선. *내용*은 무서워도 *형식*은 완전 건조해야 |
| 직무 편람 (체계·등급·지침) | 거의 0% | 동일. 분류 표가 글리치되면 "장난 같다"는 인상이 생김 |
| 사상체 문서 | 중간 (본문 내) | 표면 양식은 건조, 본문에서 호러가 *내용으로* 발현. 검열 자체가 호러 |
| 접근 거부 / 404 / 권한 부족 | 높음 | 시청자와 시스템의 *마찰점*. 호러 연출의 자연 자리 |
| 유휴 효과 / 백그라운드 | 낮음 (간헐적) | 페이지 방치 시 노이즈, 마우스 오버 글리치 등 이스터에그형 |

원칙: **구조 페이지는 거의 완전 건조하게, 마찰점과 사상체 본문에서만 호러를 끌어올린다.**

## 7. 작업 단계 순서

```
1. 기획              ← 완료
2. 콘텐츠 작성        ← 진행 중
3. 디자인 / UI 시안
4. 개발 (React)
5. 배포 전 검수
6. 데뷔
```

### 7.1. 콘텐츠 작성 순서 (단계 2 내부)

Tier 1 안에서 다음 순서로 진행:

1. **1-1 본국 개요** — 기준 페이지. 어휘·문체·검열 비율이 여기서 정해짐. 모든 다른 페이지가 이 페이지의 톤을 기준으로 함.
2. **2-A 사상체 체계 전체 (4페이지)** — 한 묶음. 위험 등급↔변칙성↔식별 코드가 서로 강하게 참조.
3. **2-B 인사·권한 체계 전체 (3페이지)** — 시청자가 *자기 위치(IG)*를 이해하는 페이지들. 데뷔 첫 시청자가 가장 빨리 만지작거릴 자리.
4. **관문 — 보안 서약서** — 2-A·2-B의 어휘 톤이 굳은 후 작성. 그 어휘를 가상 법조항에 활용.
5. **1-3 조직 구성도 + 부서 4페이지**
6. **2-C 운영 지침 전체**
7. **3-1 사상체 일람 + 3-3 검열 표기 규약**

이후 Tier 2, 그 다음 Tier 3.

### 7.2. 병행 트랙

**3-1-1 노스포비아 사상체 문서** — Tier 1 순차 작업과 별개로 언제든 시작 가능. 워낙 큰 작업(10~20쪽 분량의 옴니버스 단편 소설급)이라 짧은 응답으로 끝나지 않으므로, 따로 일정 잡고 단편 연재처럼 진행.

## 8. 단계 4 기술 메모

본 절은 단계 4(개발) 시 적용되어야 할 *기획적 결정*을 메모한다. 구현 상세는 단계 4에서 정의.

### 8.1. 인트로 페이지 — 일일 스킵

- 첫 방문 시 풀 인트로 연출 강제 (접속 게이트 부팅 시퀀스 전체).
- 같은 날(자정 기준) 재방문 시 자동 스킵 → 로그인·보안 서약서 절차를 통과한 경우 메인 대시보드로 직진.
- 메인 대시보드 어딘가에 *인트로 재생* 버튼을 두어 언제든 다시 볼 수 있도록 함. 단 그 버튼은 *눈에 띄지 않는* 위치에 — 호기심 있는 사용자만 발견.
- 구현 기반: 계정의 *최종 접속일* 필드(서버 DB). 비로그인 익명 방문자에 한해 LocalStorage (`intro_last_seen_date`) 보조 — 회원가입 전 첫 인트로의 스킵 판단용.

### 8.2. 보안 서약서 — 계정 종속 동의 저장

- 회원가입 직후 1회 강제 표시. 동의하지 않으면 메인 대시보드 진입 차단.
- 한 번 동의하면 *계정의 서약서 동의 필드*에 영구 저장. 재로그인 시 표시하지 않음.
- 서약서 *버전*이 갱신되면 모든 계정에 재동의 발동 (계정의 동의 필드가 *이전 버전*으로 기록된 사용자에게).
- 구현 기반: 서버 계정 필드 (`security_oath_agreed_version`).

### 8.3. 접근 불가 페이지 처리

- 1-4 지휘 체계, 1-5 본국 시설, 3-1-x 기타 사상체 등의 *접근 불가* 페이지는 메뉴/링크 자체는 정상 표시.
- 클릭 시 별도 화면(권한 부족 알림)으로 전환. 호러 연출 강함.
- *접근 불가* 페이지마다 미세하게 다른 알림 문구를 두는 것이 미학적으로 더 좋음 (구현 시 결정).

### 8.4. 유휴 효과

- 페이지 방치 시 (예: 3분 이상 마우스/스크롤 비활성) 미세한 노이즈/글리치 효과.
- 사용자 조작 감지 시 원상 복귀.
- 호러 연출은 *낮음~중간* 수준. 가독성 방해 최소화.

### 8.5. 로그인 / 회원가입 시스템 (통합 페이지)

본 시스템은 *IG 등급 임시 인가*의 인-유니버스 절차로 포장된 *실제 계정 시스템*이다. 데이터는 서버 DB에 저장된다. 로그인과 회원가입은 *단일 URL `/login`* 안에서 *모드 토글*로 운영된다.

#### 8.5.1. 페이지 진입과 모드 토글

- *기본 진입 시 로그인 모드*. 진입 직후 폼 제목: *IG 등급 인가 확인*.
- 폼 하단의 *[회원가입 신청]* 링크 클릭 시 같은 페이지·같은 컨테이너 안에서 *회원가입 모드*로 전환. 폼 제목: *IG 등급 임시 인가 신청*. URL은 그대로 `/login` 유지.
- 회원가입 모드에서 *[로그인]* 링크 클릭 시 로그인 모드로 복귀.
- 모드 전환은 *페이지 새로고침 없이* 컨테이너 내 상태 변경. 폼의 위치·치수는 유지되어 시각적 점프가 최소화된다.
- *식별번호*는 사상체 *식별코드*(`Aj-06-SP-0341` 등)와 어휘 분리를 위해 다른 명칭을 사용한다.

#### 8.5.2. 로그인 모드 — IG 등급 인가 확인

- 입력 항목 2개:
  - **식별자** — 계정 ID. placeholder: *계정 ID*
  - **식별번호** — 계정 비밀번호. placeholder: *계정 PASSWORD*
- 버튼: *확인*.
- 인가 성공 시 메인 대시보드로 이동. 단 *서약서 버전 갱신* 등으로 재동의가 필요하면 서약서 페이지를 경유.

#### 8.5.3. 회원가입 모드 — IG 등급 임시 인가 신청

- 입력 항목 3개:
  - **사용자명** — 노출되는 닉네임. placeholder: *노출 닉네임*
  - **식별자** — 계정 ID. placeholder: *계정 ID*
  - **식별번호** — 계정 비밀번호. placeholder: *계정 PASSWORD*
- 버튼: *신청*.
- 신청 직후 *보안 서약서* 페이지로 이동 (§8.2).

#### 8.5.4. 세션 — 24시간 비활성 만료

- 마지막 활동 기준 *24시간 경과* 시 자동 로그아웃.
- 24시간 안의 재접속(브라우저·컴퓨터 종료 후 재실행 포함)에는 로그인 유지.
- 24시간 경과 후 재접속 → 로그인 페이지(`/login`, 로그인 모드)로 진입.
- 구현 기반: 만료일이 *마지막 활동 + 24시간*으로 갱신되는 영속 쿠키 또는 서버 세션 토큰.

#### 8.5.5. 데이터 저장

- 서버 DB에 다음 계정 필드 저장:
  - `사용자명` / `식별자` / `식별번호`(bcrypt 등으로 해시 저장) / `가입일` / `최종 접속일` / `security_oath_agreed_version`
- *식별번호*는 *해시 저장* 필수. 평문 저장 금지.

#### 8.5.6. 컨셉상 플로우

```
최초 접속:
  접속 → 인트로 → 로그인 페이지 [회원가입 모드로 토글]
                 → 신청 → 보안 서약서 동의 → 메인 대시보드

재방문 (24시간 안):
  접속 → 인트로 (일일 스킵 적용) → 메인 대시보드 직진

재방문 (24시간 경과):
  접속 → 인트로 (일일 스킵 적용) → 로그인 페이지 [로그인 모드] → 메인 대시보드
  (서약서 버전 갱신이 있었으면 로그인과 메인 사이에 서약서 재동의)
```

#### 8.5.7. 메인 대시보드의 접속자 정보 영역

메인 대시보드 헤더 직하에 *접속자 정보 영역*을 둔다. 표시 항목:

```
[접속자] {사용자명} · IG · 접속일자: YYYY-MM-DD · 인가 만료: YYYY-MM-DD ██:██
```

- *인가 만료*는 마지막 활동 + 24시간. 시·분은 검열 표기(`██:██`)로 미학 디테일.
- 매일의 접속일자 갱신과 인가 만료 표시가 *IG 등급 = 임시 인가*의 컨셉을 매번 환기.
