# 노스포비아 웹사이트 작업 진행 상태

> 본 문서는 *진행 상태 추적*만 담당한다. *왜 그렇게 설계되었는지*는 진실 출처 문서에 위임한다.

## 본 문서의 사용법 (LLM용)

1. 새 세션에서 사용자가 *"웹사이트 작업 진행해줘"*, *"다음 페이지 만들자"*, *"이어서 작업"* 같은 요청을 하면 **본 문서를 먼저 읽는다**.
2. §1에서 *현재 어디까지 완료되었는지*, §2에서 *다음 작업이 무엇인지* 파악한다.
3. §3 진실 출처 라우팅 표에서 *어떤 결정을 어느 문서에서 확인해야 하는지* 식별한다.
4. 사용자에게 *"현재 X 작업 단계입니다. 다음은 Y입니다. 진행할까요?"* 식으로 짧게 컨텍스트를 환기한 뒤 작업을 시작한다.
5. 마일스톤(페이지 mockup 1개 완료 등) 단위로 본 문서를 갱신한다.

## 진실 출처와의 관계

- 본 문서는 *상태 추적*만 함. 페이지 구조·골격·기획 결정은 [`사이트구조.md`](사이트구조.md)와 [`웹사이트_기획_확정.md`](웹사이트_기획_확정.md)가 진실 출처.
- *완료된 mockup의 시각 결정*(컬러, 폰트, CRT 효과 수치 등)은 [`디자인_기획.md`](디자인_기획.md)로 *추출*되어 정리된다. 본 문서에는 *어떤 결정이 mockup에 굳어졌는지*만 기록하며, 디자인 기획에 추출된 후에는 *그 문서로 위임*된다.
- 본 문서가 다른 문서와 충돌하면 *다른 문서가 우선*. 본 문서는 그 갱신을 따라가야 한다.

### 1.2. v2.0 기준 핵심 결정 사항 (LLM이 빠르게 기억해야 함)

- **3 레이어 구조** (v2.0 §2):
  - *OS 레이어* — Win98 + WebCore. 부팅(CLI 인트로) → CLI 로그인 → Win98 데스크탑. 부속 프로그램(내 컴퓨터·휴지통·메모장)은 접근 거부 호러 자리
  - *관리국 시스템 레이어* — 2000년대 정부 인트라넷. 데스크탑의 *관리국 시스템* 아이콘 더블클릭으로 진입. 보안 서약서 → 메인 대시보드 → 본국 안내·직무 편람·자료실·공지
  - *문서 레이어* — 페이지의 80%는 *공용 문서 레이아웃*. v2.0 §10에서 *3계층 분류*로 정착: 1계층 공용 기본형(강제 아님, 응용 가능) / 2계층 적용 패턴 3종(**①본문형·②절차형·③항목형**) / 3계층 사상체 문서 시스템(5탭 + 사상체 전용 요소 + 선택적 콘셉 테마)
- **공용 문서 레이아웃 — 핵심 정책** (v2.0 §10):
  - 1계층은 *강제가 아닌 기본형*. 각 문서는 응용 가능
  - *표·매트릭스형 폐기* — 위험 등급·보안 등급 같은 페이지는 *③ 항목형*으로 (표 없이 항목별 나열 + 이미지 + 설명)
  - *법조항형* = ② 절차형의 응용 / *규칙괴담형* = ② 절차형의 응용 / *목록·인덱스형* = ③ 항목형의 변종
  - *콘셉 테마 변경*은 **사상체 문서에 한정**. 모든 사상체에 적용되는 것이 *아니라* 사상체별로 선택. 적용 시 5탭 모두에 일관 적용
  - *사상체 일람·검색 결과·메인 대시보드·접근 거부* 등은 *문서가 아닌 별도 페이지 골격* (v2.0 §10.4)
- **모바일 분기** (v2.0 §7.2): OS 레이어 우회. 짧은 부팅 애니메이션 → 행정 폼 톤 로그인 → 서약서 → 관리국 시스템 본체

#### 1.3.1. 인트로 페이지 (`access.html`) — 굳어진 시각 결정

- 검은 배경 + CRT 미감 (스캔라인 + 노이즈 + 비네팅 + 스캔빔 + 미세 깜빡임)
- 폰트: `Cascadia Code` 우선, 모노스페이스 폴백 체인
- 부팅 로그 5단 페이즈 (BIOS/OS → 보안·네트워크 → 인트라넷 접속+가상어휘 → 세션동기화 → IG 게이트)
- 로그 본문은 *전부 영문*. 한글은 mockup 검토용 컨트롤(우하단 버튼)에만 존재 — 실배포 시 제거 대상.
- 호러 균열: 약 8% 확률, 발동 시 0.7초 화면 흔들림 + 밝기·반전 필터 + 스캔라인 플래시. 평소엔 발생 안 함.
- 노스 본인 흔적: `[WARN] Cell Aj-06-SP-0341 :: anomalous signal (within tolerance, t=+47s)` — 160줄 중 한 줄로 빠르게 흐름.

#### 1.3.2. 로그인/회원가입 페이지 (`login.html`) — 굳어진 시각 결정

- 인트로와 동일한 CRT 시각 언어 (스캔라인·노이즈·비네팅·스캔빔·깜빡임)
- 접속 성공 로그 4줄 (영문) → APMB 진입 패널 → 안내 페이즈 (한글)
- **APMB 진입 패널**: 위·아래 78자 분할선 + 7행 `#` ASCII 배너 (글로우) + 메타 3행 (System / Operated by / Gate) + `— CLASSIFIED · GOVERNMENT USE ONLY —`
- **안내 페이즈**: *"APMB 인트라넷에 성공적으로 접속하였습니다. ... [1] 계정 접속 [2] 계정 등록"*
- **CLI 프롬프트 주소**: `IG@10.42.7.187:~$ ` — 시청자의 실제 IP가 아니라 *APMB 게이트웨이가 IG 세션에 부여한 가상 주소*. 접속 로그의 `Provisional address assigned :: 10.42.7.187/22`로 컨셉 정합.
- **CLI 명령 시스템**: 슬래시(`/`)로 시작하는 입력은 명령. `/help`, `/login`, `/signup`, `/whoami`, `/clear`, `/exit`(거부됨). 잘못된 명령은 `[ ERR ] unknown command: /xxx` 출력.
- **단계별 입력**: 선택 단계(1/2) → 모드 진입 후 라벨이 표시된 프롬프트 (`식별자 입력 > `, `식별번호 입력 > `, `사용자명 입력 > `). 일반 텍스트는 현재 단계의 답으로 처리. 잘못된 입력은 *재안내*.
- 식별번호는 입력 시 `•` 마스킹.
- 종료 후 전환: 로그인 성공 → `/` (메인 대시보드) / 회원가입 성공 → `/oath` (보안 서약서).

## 5. 작업 단계 순서와 단계 진입 완료 조건

```
1. 기획              ← 완료 (웹사이트_기획_확정 v2.0)
2. 콘텐츠 작성        ← 진행 중
3. 디자인 / UI 시안   ← mockup 진행 중, 디자인_기획.md 작성 진입
4. 구현 / 개발        ← 구현 결정 문서 작성 후 진입
5. 배포 전 검수
6. 데뷔
```

각 단계가 다음 단계로 진입하기 위한 최소 조건:

- *단계 1 → 2*: 기획 문서 v2.0 확정 → ✅ 완료
- *단계 2 → 3*: Tier 1 콘텐츠 중 *기준 페이지(1-1)*가 작성되어 톤·어휘가 굳음. 모든 Tier 1 완료를 기다리지 않음 — 디자인은 *기준 페이지의 톤*만 있으면 시작 가능
- *단계 3 → 4*: [`디자인_기획.md`](디자인_기획.md)가 §1(토큰)·§2(레이어별 시각)·§3(페이지별 골격) 모두 핵심 결정으로 채워지고, mockup이 대표 페이지 10건 이상 누적
- *단계 4 → 5*: Tier 1의 80% 이상 페이지가 사이트에 등재되고 핵심 기능(로그인·검색·댓글·추천)이 동작
- *단계 5 → 6*: 크로스브라우저 검수, 호러 연출 톤 최종 조정, 비기능 요구사항(성능·반응성) 통과
