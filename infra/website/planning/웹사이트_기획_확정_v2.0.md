# 1. 개요

## §0. 정의

> 본 사이트는 *Win98 시대의 격리된 워크스테이션* 위에서 동작하는 *초상현상관리국 인트라넷*이며, 외부 탐사자(IG 등급)에게 임시 인가된 *관리국의 표면 자료*를 열람·신청·반응하는 공간이다.

## §1. 핵심 전략

### §1.1. 사이트의 정체

- *컨셉상 표면*: 관리국 직원·임시 인가 탐사자가 사용하는 *관리국 내부 인트라넷*
- *실제 사용자*: IG 등급으로 임시 인가된 외부 탐사자(시청자)
- *주된 타겟 관객*: 데뷔 전 홍보로 유입된 호기심형 마이너 장르 팬

### §1.2. 전략

> *데뷔 시점 사이트의 무게중심 90%는 관리국 내부 자료. 사상체 자료는 노스포비아 1편만 정식 등재, 나머지는 의도적인 빈 자리(접근 불가)로 둔다. 호기심 유입자가 "진짜 정부 인트라넷에 들어왔다"고 느끼게 만드는 것이 1순위 목표.*

이유:
- 관리국은 사상체보다 더 큰 무대다. 무대가 정교하면 단 한 명의 배우(노스포비아)만 등장해도 무게가 실린다.
- 마이너 장르 팬은 *세계관의 깊이*에 반응한다. 사상체 개수가 아니라 *제도적 디테일*이 진짜 정부 같다는 인상을 만든다.
- 빈 자리(접근 불가)는 *부족*이 아니라 *의도된 떡밥*이 된다. 적게 만들수록 빈 자리가 미스터리가 된다.

## §2. 레이어 구조

본 사이트는 세 개의 분리된 *레이어*로 구성된다. 각 레이어는 *별도의 정체와 톤*을 가지며, 시청자가 *통과 의례*를 거쳐 다음 레이어로 진입한다.

### §2.1. OS 레이어 — Win98 데스크탑

- 컨셉상 *관리국이 IG 등급 탐사자에게 지급한 워크스테이션의 운영체제*
- 표면 모티브: Windows 98 + Webcore 미학
- 구성: 부팅 시퀀스(CLI 콘셉) → 로그인(CLI 콘셉) → 데스크탑 → 시작 메뉴·태스크바·시계
- 데스크탑 위에 *관리국 시스템* 프로그램 아이콘이 핵심. 그 외 부속 프로그램(내 컴퓨터·휴지통·메모장 등)은 *접근 거부* 호러 연출 자리
- *통과 의례*로서의 미니멀 — 콘텐츠 그 자체가 아님. 풍부함보다 *건조한 부팅의 의례성*이 우선

### §2.2. 관리국 시스템 레이어 — 관리국 인트라넷 본체

- 데스크탑의 *관리국 시스템* 아이콘을 실행하면 진입
- 본 사이트의 *핵심 콘텐츠 공간*. 사이트맵·페이지의 대부분이 여기 속함
- 톤: *2000년대 정부 인트라넷*, 건조하고 불길, 관료적·형식적
- 진입 시 보안 서약서(최초 1회) 통과 후 메인 대시보드 진입

### §2.3. 문서 레이어 — 공용 문서 레이아웃

- 관리국 시스템 레이어 안의 *대부분의 콘텐츠 페이지*는 *문서*다. 사상체 문서뿐 아니라 사상체 정의·각종 체계·운영 지침·공지가 모두 *문서*에 해당.
- 본 사이트는 *공용 문서 레이아웃*을 *기본형*으로 제공한다. **강제가 아니라 응용·변형 가능한 기본 틀**이며, 각 문서는 자유롭게 응용할 수 있다. *콘셉별 테마 변경*은 *사상체 문서에 한정*되며, 사상체의 콘셉에 따라 *적용할 수도 있고 안 할 수도 있다*.
- 자세한 결정은 §10. 공용 문서 레이아웃 정책.

### §2.4. 레이어 간의 관계

```
[OS 레이어]                      ← PC 진입 시 통과
  바탕화면 + 관리국 시스템 아이콘
    ↓ 더블클릭
[관리국 시스템 레이어]              ← 사이트의 본체
  대시보드 + 본국 안내·직무 편람·자료실·공지
    ↓ 각 페이지 진입
[문서 레이어]                    ← 페이지의 80%가 문서
  공용 문서 레이아웃 (기본형) + 적용 패턴 + 사상체 문서별 테마 (선택)
```

모바일은 OS 레이어를 우회하여 관리국 시스템 레이어로 직접 진입한다 (§7.2).

# 2. 연출

본 묶음은 *사이트가 어떻게 말하고 보이는가*의 *원리*를 다룬다. 시각적 형상 자체는 디자인 명세 문서로 위임하되, *어휘·표기·연출 강도의 결정*은 기획 영역에 둔다.

## §4. 명명 규칙

- 정식 명칭: **초상현상관리국**
- 약칭: **관리국**
- 1인칭 자칭 (문서 내부): **본국**
- 외부 탐사자 등급: **IG 등급** (Investigator)

## §5. 검열 기준

본 사이트의 검열은 *IG 등급 사용자가 열람 권한이 없는 정보*를 기준으로 한다. 컨셉상 다른 보안 등급들이 존재하지만, 실 사용자가 IG 등급뿐이므로 검열은 IG 단일 기준으로 단순화한다.

검열 표기 5종:

- `█` (검은 박스): 의미를 특정할 수 있는 단어·이름·숫자 단위
- `[데이터 말소]`: 텍스트 블록 단위
- `[기밀 분류]`: 사용자의 등급 미달
- `[기록 보류]`: 사건 진행 중 또는 결론 미확정
- 검열 길이는 원문 길이와 비례 — 가린다는 사실 자체가 "여기에 무엇이 있다"는 정보가 됨

검열 표기의 *세부 사용 규칙*(어느 상황에 어느 표기를 쓰는가)은 3-3 *검열 표기 규약* 페이지에서 다룬다. 본 절은 *5종이 존재한다*는 기획 결정만 명시한다.

## §6. 호러 연출

호러 연출 = 페이지 표면에 호러 장르 요소가 얼마나 노골적으로 드러나는가. 페이지 종류에 따라 다르게 배치한다.

| 페이지 종류 | 호러 연출 | 이유 |
|---|---|---|
| OS 레이어 부팅·CLI 인트로·로그인 | 중간~높음 | 첫인상이 분위기를 결정. 부팅·로그·인가 확인 연출 |
| OS 레이어 데스크탑 유휴 | 낮음~중간 (간헐적) | 방치 시 노이즈·미세한 글리치 |
| OS 레이어 접근 거부 프로그램 | 높음 | 부속 프로그램 클릭 시 권한 부족 알림. 호러 자연 자리 |
| 보안 서약서 | 중간 | 인-유니버스 법조항·규약의 *어휘 자체*가 균열의 자리. 시각적 호러 효과는 절제 |
| 로그인·회원가입 폼 | 거의 0% | 행정 양식의 건조한 *모드 토글* 톤 |
| 메인 대시보드 | 낮음 (가끔 균열) | 일상감 유지. 단 *최근 사건* 등에 가끔 이상한 게 노출 |
| 기관 안내·조직 구조 | 거의 0% | 신뢰감 우선. *내용*은 무서워도 *형식*은 완전 건조해야 |
| 직무 편람 (체계·등급·지침) | 거의 0% | 동일. 분류 표가 글리치되면 "장난 같다"는 인상이 생김 |
| 사상체 문서 | 기본 *중간* / 사상체별 ±조절 가능 | 공용 문서 레이아웃의 *3계층 사상체 문서 시스템* 위에서 기본 강도는 *중간*이며, *§10.3 사상체 문서별 콘셉 테마*로 *콘셉이 강한 사상체에 한해* 위·아래로 조절 가능 (모든 사상체에 적용되는 것은 아님) |
| 검색 결과 페이지 | 낮음 | 행정 조회 톤. 단 *검열된 항목*이 결과에 섞일 때만 미세 균열 |
| 접근 거부 / 404 / 권한 부족 | 높음 | 시청자와 시스템의 *마찰점*. 호러 연출의 자연 자리 |
| 유휴 효과 (관리국 시스템 내) | 낮음 (간헐적) | 페이지 방치 시 노이즈, 마우스 오버 글리치 등 이스터에그형 |

**원칙**: 구조 페이지는 거의 완전 건조하게, *마찰점과 사상체 본문*에서만 호러를 끌어올린다.

*호러 연출의 수단*(글리치·노이즈·CRT 오버레이·타이포 변형 등 *어떤 효과를 어떻게 구현할지*)은 디자인 명세 문서와 mockup 단계에서 결정한다. 본 절은 *어디에 어느 강도로 둘 것인가*만 결정.

## §3. 시각적 톤의 기획 원리

본 절은 *시각적 톤이 갖춰야 할 원리*를 다룬다. 구체 수치(컬러 코드·폰트 크기·여백·아이콘 형상 등)는 모두 *디자인 명세 문서*로 위임한다.

- **OS 레이어의 톤**: Windows 98 + Webcore 미학. *부팅·CLI·픽셀 폰트*의 의례성
- **관리국 시스템 레이어의 톤**: 2000년대 정부 인트라넷, 관료적, 형식적, 건조하고 불길
- **상징색의 원리**:
  - *관리국 상징색*과 *노스포비아 고유 상징색*은 *분리되어* 존재한다.
  - 두 상징색은 *대비*가 명확해야 한다 — 노스포비아 문서로 진입할 때 관리국 톤에 노스포비아 상징색이 *물듦*(§10.2)의 연출이 시각적으로 선명해야 하기 때문이다.
  - 관리국 상징색은 *바탕*, 노스포비아 상징색은 *침투*의 역할을 가진다.
- **구체 색·수치는 디자인 명세 문서의 영역**. 본 문서는 *어떤 원리를 따르는가*만 결정한다.

# 3. 구조

## §7. 플로우

본 절은 시청자가 *최초 진입부터 관리국 사이트 본체까지 도달하는 한 번뿐인 의례*를 정의한다. 세션 중의 페이지 이동에 쓰이는 도구는 §9 *네비게이션 원칙*에서 다룬다.

### §7.1. PC 플로우

```
링크 접속
  ↓
[CLI 인트로] — 컴퓨터 부팅 시퀀스의 시각화
  ↓
[CLI 로그인] — 식별자·식별번호 입력 (CLI 콘셉)
  · 신규 사용자는 같은 화면에서 회원가입 모드로 토글 가능
  ↓
[Win98 데스크탑] — 바탕화면·태스크바·시계·부속 프로그램 아이콘
  ↓
바탕화면의 "관리국 시스템" 아이콘 더블클릭
  ↓
[보안 서약서] — 최초 1회 강제 (또는 서약서 버전 갱신 시 재동의)
  ↓
[관리국 시스템 메인 대시보드]
```

- 인트로·로그인의 *위치*: OS 레이어의 *부팅 의례*에 속함. 관리국 시스템 진입 시 다시 발생하지 않음.
- 재방문 (24시간 안): 인트로 일일 스킵(§14) 적용 → Win98 데스크탑으로 직진. 서약서는 동의 이력이 있으면 생략.
- 재방문 (24시간 경과): 로그인 페이지부터 다시.

### §7.2. 모바일 플로우

```
링크 접속
  ↓
[CLI 인트로 (단축판)] — PC와 동일한 CLI 콘셉, 단 부팅 로그를 대폭 축소하여 3~4초 가량
  ↓
[CLI 로그인/회원가입] — PC와 동일한 CLI 콘셉, 모바일 키보드·터치 친화적 레이아웃
  ↓
[보안 서약서] — 최초 1회, 모바일 레이아웃
  ↓
[관리국 시스템 메인 대시보드] — 모바일 레이아웃
```

- 모바일은 *OS 레이어(데스크탑·창 관리·부속 프로그램)를 우회*하되, *CLI 콘셉의 시각 언어*는 인트로·로그인에서 일관 유지. PC의 11초 부팅을 *축약된 3~4초 부팅*으로 단축하여 모바일의 *빠른 진입* 요구와 *컨셉 일관성*을 균형 있게 충족한다.
- 톤의 핵심(검열 표기·접근 거부 호러·CRT 효과·서약서 어휘)도 모바일 전 구간에서 유지된다.

### §7.3. 인-유니버스 명분

- *PC 사용자*: 관리국이 IG 등급 탐사자에게 지급한 *정규 워크스테이션*에 접속. 보안상 외부 인터넷이 차단되어 있고, *관리국 시스템 프로그램*만 정상 동작. 다른 OS 기능은 *권한 부족*으로 차단.
- *모바일 사용자*: *임시 모바일 접속 모드*. 인트라넷 본체에는 도달 가능하나 *워크스테이션 환경(데스크탑·창 관리·부속 프로그램)은 제공되지 않음*. §7.2의 *CLI 인트로 단축판*은 정규 워크스테이션의 전체 부팅 의례를 모바일에서 그대로 모방하는 것이 아니라, *모바일 접속 경로에 맞춰 축약된 인가 절차*다. 관리국이 *공식 지원하는 부수적 접근 경로*이며, 부팅·로그인의 CLI 콘셉은 PC와의 *시각 언어 일관성*을 위해 유지된다.

## §9. 네비게이션 원칙

본 절은 *세션 중에 시청자가 페이지 사이를 이동할 때 쓰는 도구*의 결정 원칙이다. 시각적 형상은 디자인 명세 문서로 위임.

### §9.1. 네비게이션 패러다임의 분리

본 사이트의 페이지 영역은 두 종류로 나뉜다:

- **위계 탐색 영역** (본국 안내·직무 편람·공지) — *카테고리 카드 + URL 위계 + 위치 경로*. 정부 사이트 방식.
- **목록 탐색 영역** (자료실·사상체 일람) — *좌측 필터 + 검색창 + 결과 카드 리스트*. 자료 데이터베이스 방식.

좌측 영역은 *목록 탐색 영역에서만* 존재하며 *해당 페이지의 필터*다. *전체 사이트 네비게이션 사이드바*는 어디에도 존재하지 않는다.

### §9.2. 공통 네비게이션 도구

- **상단 메뉴** (4개): 본국 안내 / 직무 편람 / 자료실 / 공지
  - 호버 시 1차 드롭다운으로 직속 하위 페이지 목록 노출
  - 2차 드롭다운 없음 — 그 이상 깊이는 카테고리 페이지의 카드로 탐색
  - 사상체 문서 페이지의 *5개 탭*은 드롭다운에 노출하지 않음. *전용 탭 메뉴*로만 접근
- **위치 경로**: 직선형 (`Top > 카테고리 > 페이지`). 메인 페이지 외 모든 페이지에 노출. 클릭 가능
- **헤더**:
  - 좌: 로고 + 사이트명
  - 우: **검색창** (§11). 모든 페이지의 헤더에 상주
- **푸터**: 저작권 표시 / 약관 / 개인정보 처리방침 / 운영 부서 표기 (가상)
  - *전체 사이트맵 펼침 기능은 두지 않음* — 본 사이트는 접근 불가 페이지가 많아 전체 노출이 적합하지 않음
- **위계 깊이**: 3단계 권장, 4단계 최대 (자료실 > 사상체 일람 > 특정 사상체 > 사건 기록 탭 등)

### §9.3. 보류 항목 정리

기존 사이트구조에서 헤더 우측에 *별도 논의 예정*으로 보류되었던 4개 항목의 결정:

| 항목 | 결정 |
|---|---|
| 검색 | **도입** — 헤더 우측 상주, 별도 결과 페이지(§11) |
| 사이트맵 | **제거** — 별도 페이지·푸터 펼침·모달 어느 형태도 두지 않음 |
| FAQ | **보류** — 본 사이트 톤과의 적합성을 포함하여 데뷔 후 재논의 |
| 글자 크기 조절 | **보류** — 접근성 기능. 데뷔 후 재논의 |

## §10. 공용 문서 레이아웃 정책

본 절은 *문서 레이어*(v2.0 §2.3)의 시각 구조 정책을 *3계층*으로 정의한다. 1계층은 *기본 시각 토큰*, 2계층은 *적용 패턴 3종*, 3계층은 *사상체 문서 시스템*이다.

### §10.1. 1계층 — 공용 문서 레이아웃 (기본형)

본 사이트의 *콘텐츠 페이지 대부분은 문서*다. 모든 문서는 *공용 문서 레이아웃*을 *기본형*으로 가진다. **강제가 아니라 응용 가능한 기본 틀**이며, 각 문서는 콘텐츠 성격에 맞게 *응용·변형*할 수 있다.

공용 문서 레이아웃의 기본 구성: *메타 박스 + 본문 + 보조 영역*. 구체 시각(컬러·여백·타이포·검열 표기)은 **디자인 기획 문서**에서 정의된다.

적용 페이지 (1계층 기본형이 적용되는 문서들):
- 1번 본국 안내의 본문 페이지 (1-1·1-2·1-3-x·1-6)
- 2번 직무 편람의 모든 본문 페이지 (2-A·2-B·2-C 하위)
- 3-1-x 사상체 문서 (5개 탭은 *3계층 응용*, §10.3 참조)
- 3-2 용어집·3-3 검열 표기 규약
- 4번 공지의 본문 페이지 (4-1·4-2·4-3 산하 개별 공지)

사이트가 *콘텐츠 자체를 작성·편집하는 기능을 제공하지 않으므로* (문서 수정·추가·삭제는 개발자가 직접 수행), 본 정책은 *시청자가 보는 화면의 공통 골격*에 한정된다.

### §10.2. 2계층 — 적용 패턴 3종

문서는 *나열 여부*와 *항목당 분량*에 따라 다음 3종 패턴 중 하나로 분류된다. 각 패턴은 *공용 레이아웃 위에서 콘텐츠 표현 방식*을 정의한다.

| 패턴 | 정의 | 주 적용 페이지 |
|---|---|---|
| **① 본문형** | 자유 서술 (나열 X) | 1-1 본국 개요, 2-C-3 격리 절차 원칙, 사상체 개요 탭, 보안 서약서 서문 |
| **② 절차형** | 1차원 번호 나열, 항목당 짧은 분량 (1~3문장) | 대응 지침, 격리 절차, 1-6 설립 근거 법령, 2-C 운영 지침 (응용: *법조항형*, *규칙괴담형*) |
| **③ 항목형** | 1차원 항목 나열, 항목당 긴 분량 + 이미지 가능 | 변칙 현상, 사건 기록, 2-A-2 위험 등급, 2-A-3 변칙성 분류, 2-B 보안 등급, 3-2 용어집 (응용: *목록·인덱스형*) |

**응용 원칙**:
- *법조항형*은 ② 절차형의 응용 (긴 조항·법률 어휘)
- *규칙괴담형*은 ② 절차형의 응용 (몰입·가독성·서사 분해)
- *목록·인덱스형*은 ③ 항목형의 변종 (짧은 항목 가나다 나열)
- *표·매트릭스에 의존하는 페이지 설계는 폐기*. 위험 등급·보안 등급 같은 페이지는 *③ 항목형*으로 (표 없이 항목별 나열 + 이미지 + 설명)

**시각 구체**는 디자인 기획 문서로 위임.

### §10.3. 3계층 — 사상체 문서 시스템

사상체 문서(3-1-x)는 공용 패턴 ①②③을 *5탭에 분산 배치*하고 *사상체 전용 요소*를 추가한 구조다. *공용 레이아웃의 응용이되 별도 시스템*으로 다룬다.

#### §10.3.1. 5탭 구조와 패턴 매핑

| 탭 | 필수/선택 | 적용 패턴 | 특이 사항 |
|---|---|---|---|
| 개요 | 필수 토대 (진입 화면) | ① 본문형 | 메타 박스 강조, 사상체 이미지 영역 |
| 변칙 현상 | 필수 토대 | ③ 항목형 | 변칙 현상별 1~2문단 설명 |
| 대응 지침 | 세 작품 중 택1 | ② 절차형 (규칙괴담 응용) | 몰입·가독성·서사 분해 |
| 사건 기록 | 세 작품 중 택1 | ③ 항목형 (나폴리탄) | 사건 코드별 긴 콘텐츠 + 이미지 첨부 가능 |
| 격리 절차 | 세 작품 중 택1 | ② 절차형 (격리픽션 응용) | 격리 환경에서의 조사·분석·연구 절차 |

각 탭은 *별도 URL의 별도 페이지*다. 탭별 필수/선택, 미노출 원칙, 메타 박스 공유 등의 결정은 사이트구조.md §3.4-D와 정합한다.

#### §10.3.2. 사상체 전용 요소

- 5탭 메뉴 시스템 (개요·변칙 현상·대응 지침·격리 절차·사건 기록)
- 사상체 전용 메타 박스 (위험 등급·식별 코드·변칙성·보안 등급 등 — `lore/사상체_정의.md` §6.1)
- 개요 탭의 *사상체 이미지 영역*
- 사건 기록 탭의 *이미지·자료 첨부 영역*

#### §10.3.3. 콘셉별 테마 변형 (선택적)

사상체의 콘셉에 따라 *시각 테마 변형*을 적용할 수 있다.

**적용 정책**:
- *모든 사상체 문서에 적용되는 것이 아님*. 사상체의 콘셉이 강할 때에 한정
- 사상체마다 *적용 여부를 결정*. 적용 안 한 사상체는 *공용 톤* 그대로
- 적용 시 *해당 사상체의 5탭 모두에 일관 적용*. 탭을 이동해도 테마는 유지
- 사상체 문서를 벗어나면 *공용 톤으로 복귀*

**변형 가능 시각 요소** (기획 차원의 예시, 구체 시각은 디자인 기획 문서로 위임):
- 사이트 전체 톤의 *물듦* — 예: 노스포비아 문서 진입 시 관리국 톤에 노스포비아 상징색이 옅게 침투
- 배경·노이즈 강도 변경
- 레이아웃 비율 변경 — 메타 박스 확장·주변 UI 축소·본문 강조
- 호러 연출 강도 조절 (§6 매트릭스의 *기본 중간 ± 조절 가능*과 정합)

레퍼런스: SCP 재단의 일부 SCP 문서가 *기본 레이아웃을 제공하면서도 특정 문서에 한해 테마·레이아웃을 변형*하는 방식.

### §10.4. 별도 페이지 골격 (문서가 아닌 페이지)

다음 페이지는 *문서가 아니므로* 공용 문서 레이아웃에 속하지 않고 *별도 페이지 골격*으로 정의된다:

- **자료실** (3-1) — 좌측 필터 + 검색 + 카드 리스트 (사이트구조 §3.4-E)
- **검색 결과 페이지** — v2.0 §11
- **메인 대시보드** — 헤더·접속자·카테고리 카드 등 (사이트구조 §3.4-A)
- **접근 거부 / 404 / 권한 부족** 화면
- **카테고리 페이지** (`/about/`·`/duty/` 등) — 카드 리스트 (사이트구조 §3.4-B)

이들은 *문서 레이아웃 패턴(①②③)과 무관*하며 각자의 골격을 가진다.

### §10.5. 위임

- *공용 문서 레이아웃의 구체 시각*(컬러·여백·타이포·메타 박스·본문 단계 등)은 **디자인 기획 문서**에서 정의한다.
- *적용 패턴 3종의 구체 시각*(번호 나열 형식·항목 카드·이미지 영역 등)도 디자인 기획 문서.
- *콘셉 테마 변형의 토큰·구현 방식*(CSS 변수·테마 토큰·렌더링 분기 등)은 **기술 구현 문서**에서 정의한다.
- 본 절은 *시스템의 존재·분류 기준·적용 정책*까지만 결정.

# 4. 기능

본 묶음은 사이트 안에서 동작하는 *기능들의 기획 결정*을 모은다. 각 기능의 *구현 방식*(라이브러리·API·데이터 구조 등)은 구현 결정 문서로 위임.

## §11. 검색

### §11.1. 범위

- 검색 대상은 *관리국 시스템 레이어 안의 모든 문서·공지·체계·지침*. 사상체 문서뿐 아니라 *각종 체계·운영 지침·공지·용어집*도 포함.
- 단 *접근 불가 페이지·검열된 항목*은 결과에 표시되나 *클릭 시 권한 부족 알림*. 일부 검열 항목은 결과에서 *미리보기 텍스트가 검열 표기로 가려진* 형태로 노출.

### §11.2. UI

- 검색창은 모든 페이지의 *헤더 우측*에 상주
- 검색 실행 시 *별도 검색 결과 페이지*로 이동
- 결과 페이지: 검색어 + 카테고리 필터 + 결과 카드 리스트 + 페이지네이션

### §11.3. 인-유니버스 포장

- 검색 안내 문구·결과 페이지의 어휘는 *건조한 행정 조회* 톤
- 예: *"검색 조건에 부합하는 자료 N건이 조회되었습니다."*

## §12. 로그인·회원가입

### §12.1. 위치와 컨셉

- *OS 레이어의 부팅 의례*에 속함. 관리국 시스템 진입 시 별도 로그인 없음.
- CLI 콘셉 — 컴퓨터 부팅 후 *사용자 계정으로 로그인*하는 과정을 시각화. mockup `login.html`이 기준.
- 한 페이지 안에서 *모드 토글*로 로그인·회원가입 두 기능 운영. 페이지 새로고침 없음.

### §12.2. 입력 항목

- **로그인 모드**: 식별자(ID) · 식별번호(PW). 2개 입력
- **회원가입 모드**: 사용자명(노출 닉네임) · 식별자 · 식별번호. 3개 입력

*식별번호*는 사상체 식별코드(`Aj-06-SP-0341` 등)와 어휘 분리를 위해 의도된 다른 명칭이다.

### §12.3. 세션과 데이터 정책

- 마지막 활동 기준 *24시간 비활성* 시 자동 로그아웃
- 식별번호는 해시 저장 필수 (구체 알고리즘은 구현 결정 문서)
- 사용자명은 *고유*(중복 불허) + *변경 불가*
  - 인-유니버스 명분: *"등록된 탐사자 식별명은 보안 기록 보존을 위해 변경할 수 없습니다."*
- 비밀번호 분실 시 복구 절차: *가입 시 입력한 비상 식별 문구*로 인증 후 재설정. 인-유니버스 포장: *"본 단말 등록 시 입력한 비상 식별 문구를 기입하십시오"*
- 계정 탈퇴 절차: 데뷔 후 재논의. 초기엔 *문의 통해 수동 처리*로 최소 운영
- 스팸 방지: 가입·로그인 폼에 봇 방지 장치 적용 (구체 방식은 구현 결정 문서)

## §13. 보안 서약서 동의

- 회원가입 직후 + *관리국 시스템 최초 진입 시* 1회 강제 표시. 동의하지 않으면 메인 대시보드 진입 차단.
- 한 번 동의하면 계정의 *서약서 동의 필드*에 영구 저장. 재진입 시 미표시.
- 서약서 *버전*이 갱신되면 *이전 버전 동의자*에게 재동의 발동.
- 인-유니버스: 가상 법조항·규약의 어휘 자체가 균열의 자리. 시각적 호러 효과는 절제.

## §14. 인트로 일일 스킵

- *첫 방문 시* 풀 인트로 연출 강제 (OS 레이어 부팅 + CLI 로그인 전체)
- 같은 날(자정 기준) 재방문 시 *부팅 시퀀스 스킵* → 로그인 또는 데스크탑으로 직진
- 데스크탑 어딘가에 *인트로 재생* 트리거를 두어 언제든 다시 볼 수 있도록 함. 단 그 위치는 *눈에 띄지 않게* — 호기심 있는 사용자만 발견

## §15. 접근 불가 페이지 처리

본 사이트의 *접근 불가* 처리는 두 종류로 나뉜다.

### §15.1. 일반 접근 불가 페이지

- *1-4 지휘 체계*·*1-5 본국 시설*·*OS 레이어 부속 프로그램*(내 컴퓨터·휴지통·메모장 등) 등의 페이지가 해당
- 메뉴·목록에는 *항목으로 정상 노출*. 회색 비활성 표시 아님
- 클릭 시 별도 *권한 부족 알림 화면*으로 전환
- 알림 문구는 페이지마다 미세하게 다름 — 미학 디테일
- 호러 연출 *높음* — 시청자와 시스템의 자연스러운 마찰점

### §15.2. 사상체 일람 페이지의 접근 처리

*3-1 사상체 일람* 안의 항목들은 *일반 접근 불가*와 다른 *권한 신청 절차*를 가진다. 본 절은 일람 페이지의 *분류·노출·분기·신청 정책*을 단일 진실 출처로 정의한다. (본 결정은 폐기된 세계관_설정 v0.6 §1.5.3의 어휘를 본 사이트의 살아 있는 결정으로 복원·정착시킨다.)

#### §15.2.1. 분류 기준

- 사상체 일람 페이지는 *보안 등급별*로 항목을 분류·정렬한다.
- **분류 기준 = 보안 등급, 분량 기준 = 위험 등급**으로 두 축이 보완 관계를 이룬다. 보안 등급은 *행정상의 열람 권한*을, 위험 등급은 *해당 사상체의 위험성*을 표현한다.
- 보안 등급이 낮아도 위험 등급이 높은 사상체, 또는 그 반대도 존재할 수 있다.

#### §15.2.2. 항목 분량

세계관_설정 §1.5.2의 결정을 따른다:

- *위험 등급 1~4*: 각 등급 ≤20개의 항목
- *위험 등급 5*: ≤5개의 항목
- 총 약 85개 항목이 *일람에 등재*되어 있되, 데뷔 시점에 *실제 열람 가능*한 것은 약 6개 (노스포비아 본체 + 입문용 5개 내외)

#### §15.2.3. 일람 페이지에 노출되는 항목 정보

각 항목에 대해 *목록 단계*에서는 다음만 노출한다:

- **식별 코드** (필요 시 검열 처리)
- **명칭** (필요 시 검열 처리)
- **보안 등급** (분류·정렬 축이므로 그룹 헤더 또는 항목 메타로 노출)

*열람 상태(열람 가능·신청 가능·반려 등)는 목록 단계에서 표시하지 않는다.* 시청자가 *항목을 직접 클릭*한 후에야 자신의 위치(권한의 한계)가 인식된다.

#### §15.2.4. 클릭 후 2가지 분기 — 도착 화면

| 분기 | 도착 화면 | 어휘 톤 | 호러 연출 |
|---|---|---|---|
| 권한 승인 | 사상체 문서 페이지 (5개 탭 중 진입 탭) | 정상 — 건조한 행정 톤 | 문서별 커스터마이즈(§10.2)에 따름 |
| 권한 반려 | *권한 반려 안내 페이지* — 반려 사실 + 내부 상태별 안내 (§15.2.5) | 행정 통지 — *"본 항목에 대한 시청자의 열람 권한은 부여되지 아니한다"* | 중간~높음 — 내부 상태에 따라 강도 가변 |

#### §15.2.5. 권한 반려 화면 — 내부 상태별 표시

*권한 반려* 페이지는 시청자의 *해당 항목에 대한 신청 이력*에 따라 안내 디테일이 달라진다. 페이지의 *상단 반려 통지*는 모든 내부 상태에서 동일하며, *하단의 안내·신청 영역*만 상태에 따라 변경된다.

**(가) 신청 가능 상태** — 시청자가 아직 본 항목에 대한 신청을 하지 않은 경우

- 표시: 반려 통지 + *열람 권한 신청* 폼·버튼
- 어휘: *"본 항목의 열람을 위하여는 본국에 대한 별도의 권한 신청을 요한다. 신청 후 본국의 심사를 거쳐 승인 여부가 결정된다."*
- 호러 연출: 낮음 (건조한 폼 톤 유지)
- 신청 폼 구성:
  - 식별 코드·명칭(자동 입력)
  - *신청 사유* 텍스트 입력 (선택 — 글자 수 제한·필수 여부는 데뷔 후 운영하면서 결정)
  - 제출 버튼: *신청*
- 제출 시 *접수 확인 메시지* 후 동일 항목의 내부 상태가 *신청 가능 → 심사 중*으로 전환

**(나) 심사 중 상태** — 시청자가 이미 신청했고 본국이 처리 대기 중인 경우

- 표시: 반려 통지 + *권한 심사 중* 상태 표시 + 신청 일자 (검열 처리 가능)
- 어휘: *"본 항목에 대한 시청자의 신청은 본국에 의하여 접수되었다. 현재 심사 중이며, 심사 결과의 통지 시점은 본국의 직무 운영 일정에 종속된다."*
- 호러 연출: 낮음~중간 (대기의 *시간 검열* 자리)
- 신청 폼 미노출. 신청 일자만 표시되며 *심사 결과 예상 시점은 표기되지 않음* — 시청자의 대기는 본국의 미결정 영역에 종속

**(다) 신청 불가 상태** — 본국이 이미 시청자의 신청을 거부했거나, 항목 자체가 신청 대상이 아닌 경우 (주로 KL 수준)

- 표시: 반려 통지 + *신청 차단* 표시. 사유는 보통 `[기록 보류]` 또는 `[기밀 분류]`로 검열
- 어휘 — *재신청 거부* 케이스: *"본 항목에 대한 시청자의 신청은 본국에 의하여 처리되었다. 재신청 가능 여부는 본국의 결정에 따른다. 결정 시점은 [기록 보류] 한다."*
- 어휘 — *신청 자체 차단* 케이스(KL 수준): *"본 항목은 IG 등급의 신청 범위를 벗어난다. 본 항목에 대한 추가 절차는 안내되지 아니한다."*
- 호러 연출: 중간(재신청 거부) ~ 높음(신청 자체 차단). *마찰점*
- 신청 폼 미노출. 재신청 가능 여부·재신청 시점 등은 본국의 결정 영역으로 *영구 보류*

#### §15.2.6. 신청 기능의 구현 수준

데뷔 시점의 *열람 권한 신청*은 다음 운영 수준으로 시작한다:

- *신청 버튼은 실제로 동작*하나, *심사 절차는 본국(개발자)의 수동 운영*. 자동 승인 알고리즘은 두지 않음
- *심사 결과*(승인·반려)는 본국의 결정에 따라 발생. 결과 통지는 사이트 내 알림 또는 *공지* 영역을 통해 안내될 수 있음
- *신청 후 심사 대기 상태*의 시청자는 동일 항목 클릭 시 반려 화면 내부의 *심사 중* 상태를 본다
- *반려된 항목*의 재신청 가능 여부·횟수 제한 등 세부 운영 정책은 데뷔 후 재논의

인-유니버스 명분: *"본국은 IG 등급 인원의 접근 권한 신청을 정기·비정기로 심사하며, 심사 결과는 본국의 결정에 따른다. 본 절차는 본국의 직무 운영 일정에 종속되므로 시청자가 통지 시점을 예측하지 못할 수 있다."*

#### §15.2.7. 미학 — *닫힌 회로*

권한 반려 화면의 세 내부 상태(*신청 가능·심사 중·신청 불가*) 모두에서 *시청자의 행위가 본국의 결정 영역에 종속*된다. 신청을 하든 안 하든, 심사 결과를 기다리든, 재신청이 가능한지 확인하든 — 모든 시점에 시청자의 *다음 단계*는 본국에 의해 결정된다. 이는 세계관의 *닫힌 회로 함의*(시청자의 권한이 본국의 결정에 무한히 종속됨)를 *행정 어휘의 표면*으로 드러내는 자리이며, 본 사이트의 호러 연출이 *어휘 자체에서* 발현되는 핵심 기점이다.

또한 *목록을 한눈에 훑어보는 단계*에서는 어느 것이 막혀 있는지가 즉시 드러나지 않으며, *클릭이라는 직접 행위*만이 시청자의 권한 한계를 가시화한다. 이는 §1.2 *의도된 빈 자리* 미학의 구체 구현이다.

알림 문구는 항목·시간·상태에 따라 *미세하게 다른 어휘 변형*을 가질 수 있다 — 예: 두 번째 반려 시 *이전 신청의 반려 이력이 본 항목의 후속 처리에 반영되었다* 같은 누적 어휘를 추가. 미학 디테일.

## §16. 유휴 효과

- 페이지 방치 시 (예: 3분 이상 마우스·스크롤 비활성) 미세한 노이즈·글리치
- 사용자 조작 감지 시 원상 복귀
- 호러 연출 *낮음~중간*. 가독성 방해 최소화
- OS 레이어와 관리국 시스템 레이어 모두에 적용. 단 두 레이어의 *연출 강도와 수단*은 다를 수 있음 (디자인 명세 문서로 위임)

## §17. 댓글·추천

### §17.1. 댓글 — 일반 커뮤니티 패턴

- 사상체 문서에 댓글 작성 가능
- *대댓글*(1단계) 허용
- 본인 댓글의 *수정·삭제* 자유
- 비로그인 사용자는 *열람 가능, 작성 불가*
- 부적절한 단어·욕설 필터링은 *최소* 적용 — 건조한 행정 폼 톤에 *과도한 자동 검열*은 부조화. 운영자 사후 처리 중심

### §17.2. 추천 — *마음 넘김*

- 사상체 문서에 *추천*(마음) 가능. 1인 1회. 철회 가능
- 인-유니버스 명칭은 *마음 넘김* 등 행정 어휘로 포장 (구체 명칭은 mockup·디자인 단계 결정)

### §17.3. 인기도 표현 — 대시보드의 *문서 흐름*

- 메인 대시보드에 *문서 흐름* 영역을 두어 *최근 활발히 반응되고 있는 문서*를 노출
- 표시 방식: *최근 N일 추천·댓글 활성도* 기준 상위 항목
- 인-유니버스 포장: *"최근 조회 활성 자료"* 또는 *"본국 내부 주목도 상위 자료"* 같은 행정 어휘
- 구체 *순위 산출 방식·노출 개수·시간 범위*는 구현 결정 문서로 위임

### §17.4. 인-유니버스 포장 원칙

- 댓글·추천이 *친목 커뮤니티*가 아닌 *관찰 기록*으로 보이도록 어휘를 행정 톤으로 포장
- 단 *기능 자체는 일반 커뮤니티 패턴* — 톤만 행정적, 동작은 익숙한 UX
