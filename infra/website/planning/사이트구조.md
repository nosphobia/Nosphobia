# 사이트 구조 확정본

본 문서는 노스포비아 웹사이트의 *구조*(네비게이션·페이지 위계·레이아웃 골격)를 확정한다. 1번 카테고리(실제 정부 사이트 3선)와 SCP 재단의 구조를 비교 분석한 결과를 토대로 함.

## 본 문서가 다루는 영역

- 1번 카테고리 사이트의 구조 분석 (Step 1)
- SCP 재단의 구조 분석 (Step 2)
- 비교 매트릭스와 노스포비아 사이트의 구조 결정 (Step 3)
- 페이지 유형별 레이아웃 골격 5종

## 본 문서가 다루지 않는 영역

- 디자인 디테일 (컬러·타이포·여백 등) — 다음 단계 `디자인_가이드_확정.md`에서 다룸
- 호러 연출 자리 — 디자인 단계 이후 별도 결정
- 콘텐츠 작성 — `웹사이트_기획_확정.md`

## 분석 차원

각 사이트는 다음 5개 차원에서 분석되었다.

1. **네비게이션 구조** — 좌측 트리 vs 상단 메뉴, 트리 깊이, 빵부스러기
2. **페이지 위계** — 메인 → 카테고리 → 서브 → 콘텐츠 흐름
3. **메인 페이지 레이아웃** — 헤더·푸터·사이드바·콘텐츠 구성
4. **문서 페이지 레이아웃** — 메타 박스, 본문 구조, 좌측 트리 유무
5. **분류·검색 시스템** — 분류 체계, 검색 UI, 필터링

## 1. Step 1 — 1번 카테고리 구조 분석

분석 대상: 일본 외무성 (MOFA, https://www.mofa.go.jp/) / 일본 후생노동성 (MHLW, https://www.mhlw.go.jp/) / 한국 국가법령정보센터 (https://www.law.go.kr/)

### 1.1. 분석 매트릭스

| 차원 | MOFA | MHLW | 국가법령정보센터 |
|---|---|---|---|
| 네비게이션 주력 | 상단 5개 메뉴 + 푸터 사이트맵 | 상단 메뉴 + 부서별 하위 도메인 | 상단 메뉴 + **검색 중심** |
| 좌측 트리 | ❌ 없음 | ❌ 없음 | 🔶 검색 결과 화면에 일부 |
| 빵부스러기 | 직선형 (`Top > About Us`) | 직선형 | 직선형 |
| 위계 표시 방식 | 카테고리 페이지의 *서브 카드 리스트* | 동일 | 분류 트리 + 검색 결과 |
| 메인 페이지 구성 | 슬라이드 + In Focus + What's New + Topics + 배너 | 유사 (공지 중심) | 검색 박스 + 분류 + 신착 법령 |
| 문서 페이지 | 좌측 트리 없음, 본문 중앙 정렬 | 동일 | 좌측 트리 (조문 위계) + 본문 |
| 분류·검색 | 단순 검색창 (메인 콘텐츠는 카테고리로) | 동일 | **분류 + 본문 검색 중심** |
| URL 깊이 | 3단계 평균 (`/about/hq/org.html`) | 3~4단계 + 서브 도메인 | 2단계 + 파라미터 |
| 푸터 | 전체 사이트맵 (대형) | 전체 사이트맵 | 약식 사이트맵 |
| 언어/접근성 | S/M/L 글자 조절 + 다국어 토글 | 동일 | 글자 조절 |

### 1.2. 핵심 통찰

#### ① 일본 정부 사이트는 *좌측 트리를 쓰지 않는다*
이는 사전 추측과 반대되는 결과다. MOFA·MHLW는 *카테고리 페이지의 카드 리스트 + 직선 빵부스러기*로 위계를 표시한다. 좌측 트리는 *위계 탐색 자체*보다 *문서 내부 구조*(법령 조문 등)에 쓰인다.

> 노스포비아가 *위계 탐색*을 위해 *반드시 좌측 트리를 써야 할 이유는 없다*. 카드 리스트 + 빵부스러기 조합도 정직한 정부 사이트 톤이다.

#### ② 두 가지 네비게이션 패러다임의 공존
1번 카테고리 안에 두 가지 패러다임이 공존:
- **위계 탐색** (MOFA·MHLW): 카테고리 → 서브 → 콘텐츠
- **목록·검색 탐색** (law.go.kr): 검색·필터 → 결과 리스트 → 본문

노스포비아도 이 두 패러다임의 공존이 필요:
- 본국 안내·직무 편람 → MOFA 스타일
- 자료실·사상체 일람 → law.go.kr 스타일

#### ③ 메인 페이지의 표준 구성 요소
세 사이트의 메인 페이지가 거의 동일한 요소를 가짐:
- 주력 슬라이드/배너 (헤드라인 사건)
- 공지/뉴스 리스트 (날짜별 What's New)
- 주제별 링크 (Topics / 분류)
- 외부 연결 (관련 기관, 소셜)
- 상단 보조 (검색, 사이트맵, FAQ, 글자 크기, 다국어)
- 푸터 사이트맵 (전체 카테고리 펼침)

이는 노스포비아 메인 대시보드의 시각적 표준 모델이며, `웹사이트_기획_확정.md` §8.2와 거의 일치한다.

## 2. Step 2 — SCP 재단 구조 분석

분석 대상: SCP 영문 (https://scp-wiki.wikidot.com/) / SCP 한국어 (https://scpko.wikidot.com/)

### 2.1. 분석 매트릭스

| 차원 | SCP 영문 | SCP 한국어 |
|---|---|---|
| 네비게이션 주력 | **좌측 사이드바 + 상단 바** | 동일 |
| 좌측 사이드바 | ✅ **모든 페이지에 노출** | 동일 |
| 상단 메뉴 | 단순 (Home / Wiki / Foundation / Community) | 동일 |
| 빵부스러기 | ❌ 거의 없음 | ❌ 거의 없음 |
| 위계 표시 방식 | **허브 페이지 + 사이드바 + 태그** | 동일 |
| 메인 페이지 구성 | 최신 항목 + 추천 + 안내 + 자매 사이트 링크 | 운영 공지 + 특집 + 안내 + 자매 사이트 |
| 문서 페이지 | **본문 + 좌측 사이드바 (사이트 전체 네비)** | 동일 |
| 분류·검색 | **태그 시스템** + 시리즈 페이지 | 동일 |
| URL 구조 | ✅ **평면** (`/scp-173`, `/foundation-tales`) | 동일 |
| 위계 깊이 | URL상 1단계 | 동일 |

### 2.2. 문서 페이지 표준 양식

```
Item #: SCP-173
Object Class: Euclid

Special Containment Procedures:
[격리 절차 본문]

Description:
[설명 본문]

Addenda:
[부록 — 사건 기록, 면담 보고, 실험 로그 등]
```

본문 시작부에 *식별 코드 + 등급*이 메타 박스로 명시되고, 그 다음 *섹션 헤더* 형태로 본문이 이어진다. 좌측에는 사이트 전체 사이드바가 *항상* 떠 있다.

### 2.3. 핵심 통찰

#### ① 좌측 사이드바는 *현재 위치 표시*가 아니라 *전체 탐색 도구*
1번 카테고리에서 좌측 트리는 *없음*. SCP는 *항상 있음*. 그러나 SCP의 사이드바는 *현재 페이지 위치를 표시하지 않음* — 사이트 전체 진입점 모음일 뿐. 어디에서든 한 번에 다른 페이지로 점프 가능. 위계 내 *현재 위치 인지*는 약하지만, *어디로든 점프 가능*한 자유도가 높음.

#### ② URL은 평면, 위계는 *허브 페이지*로 만들어짐
SCP에서 위계는 *URL이 아니라 페이지 간 연결*로 표시됨:
- Tales Hub → Series Archive, Canon Hub, Top Rated Tales 등의 하위 허브
- Groups of Interest Hub → 각 단체 페이지

URL은 전부 `/페이지명` 평면이지만, *허브 페이지가 사실상 카테고리 페이지 역할*. 1번 카테고리의 *About Us 카테고리 페이지*와 SCP의 *Tales Hub*는 기능적으로 동일하다 — 둘 다 *서브 페이지 카드 리스트*. 차이는 URL이 폴더 구조인가(`/about/`) vs 평면인가(`/tales-hub`)일 뿐.

#### ③ 태그 시스템 = 다중 분류
1번 카테고리에서는 한 페이지가 *한 카테고리*에 속함 (URL 폴더로). SCP에서는 한 페이지가 *여러 태그*를 가짐 — 예: SCP-173 → `scp`, `euclid`, `sculpture`, `autonomous`, `hostile`, `featured`, `cognitohazard`.

이 태그들로 *동적 분류·필터링*이 가능. 노스포비아의 *사상체 분류 체계*(이름·식별코드·분류등급·위험등급·인식조건·소속·계열)가 태그 시스템으로 구현 가능하다는 시그널이다.

### 2.4. 두 패러다임의 결정적 차이

| 방식 | 1번 카테고리 | SCP 재단 |
|---|---|---|
| 비유 | **"지도 위에서 길 찾기"** | **"사이드바 친구 따라가기"** |
| 위계 구현 | URL 폴더 깊이 + 빵부스러기 + 카테고리 카드 | 좌측 사이드바 + 허브 페이지 + 태그 |
| 강점 | 현재 위치 명확, 위계 인지 강함 | 어디서나 어디로든 점프 가능, 탐색 자유도 |
| 약점 | 다른 페이지 점프 시 빵부스러기 거슬러 올라야 함 | 현재 위치 인지 약함, 위계 깊은 콘텐츠 표현 어려움 |

## 3. Step 3 — 비교 매트릭스 + 노스포비아 구조 결정

### 3.1. 통합 비교 매트릭스

| 차원 | 1번 카테고리 | SCP 재단 | **노스포비아 결정** |
|---|---|---|---|
| 좌측 사이드바 | ❌ 없음 | ✅ 항상 노출 | ❌ **기본 없음** (단, 자료실에선 *필터 영역*으로) |
| URL 위계 | 깊음 (3단계+) | 평면 (1단계) | **깊음** |
| 빵부스러기 | ✅ 직선형 | ❌ 거의 없음 | ✅ **직선형** (모든 페이지) |
| 위계 표시 | URL + 빵부스러기 + 카테고리 카드 | 허브 페이지 + 사이드바 + 태그 | **URL + 빵부스러기 + 카테고리 카드** |
| 메인 페이지 | 슬라이드+공지+카테고리 | 최신활동+추천+안내 | **공지·사건 중심** (슬라이드 없음) |
| 문서 메타 | 본문 시작부에 짧게 | **본문 시작부 메타박스** | **메타 박스 채택** (SCP 양식) |
| 문서 사이드바 | ❌ 없음 | ✅ 사이트 네비게이션 | ❌ **사이트 네비 사이드바 없음** + ✅ *사상체 문서 페이지 한정* 본문 우측에 *세로 사이드 메타 박스* (문서 운용 정보용. 사이트 네비 아님) |
| 본문 섹션 | 자유 | **고정 섹션** | **고정 섹션 채택** |
| 분류 방식 | URL 폴더 (단일) | 태그 (다중) | **하이브리드** — URL 단일 + 자료실 필터에선 태그식 다중 |
| 검색 | 보조 | 태그·시리즈 강력 | **자료실에 강력**, 그 외 보조 |
| 자매 사이트 | 푸터 사이트맵 | 푸터 + 사이드바 | **푸터 사이트맵** |

### 3.2. 결정의 근거 — 4가지 원칙

#### ① *시각·구조 표면*은 1번 카테고리, *콘텐츠 발견*은 SCP
"진짜 한국 정부 인트라넷처럼 *보여야*" 한다는 컨셉 1순위 목표에 따라, 시청자 첫인상을 만드는 *시각·구조의 표면 90%*는 1번 카테고리 방식이다. 한편 *콘텐츠(사상체)를 발견하는 방식*은 SCP의 강점인 *고정 메타 박스 + 섹션 구조 + 태그식 필터*를 가져온다.

#### ② *위계 탐색 영역*과 *목록 탐색 영역*을 분리
사이트의 영역을 두 종류로 나눔:

- **위계 탐색 영역** (본국 안내, 직무 편람, 공지) → MOFA 방식. 카테고리 카드 + URL 깊이 + 빵부스러기. 좌측 트리 없음.
- **목록 탐색 영역** (자료실 / 사상체 일람) → 한국 국가법령정보센터 방식 + SCP 태그 시스템. *좌측 필터 + 검색창 + 결과 리스트*. 이때만 *좌측 영역*이 존재하지만, 이는 *전체 사이트 네비게이션*이 아니라 *해당 페이지의 필터*. SCP의 좌측 사이드바와는 결이 다름.

#### ③ 사상체 문서 페이지의 양식은 `lore/사상체_정의.md`를 진실 출처로 채택
사상체 문서 페이지의 *메타 박스 항목*과 *본문 섹션* 정의는 `lore/사상체_정의.md` §6.1·§6.2가 진실 출처다. 본 문서는 시각 배치만 결정한다.

시각 배치는 SCP 양식을 참고하되 다음 두 결정을 둔다:
- *좌측 사이드바는 없음* — 본문이 화면의 중심에 옴 (1번 카테고리 톤과 호환).
- *본문 우측*에 얇은 *사이드 메타 박스*를 둠 (작성일·갱신일·작성 부서·관련 항목·문서번호 등 *웹사이트 운영 정보*). 이는 진실 출처에 정의되지 않은 자리이며, 본 문서가 *웹사이트 측 보조 영역*으로 추가하는 골격이다.

#### ④ 위계 깊이는 *3단계 권장 / 4단계 최대*
1번 카테고리의 평균 깊이(3단계)와 `웹사이트_기획_확정.md` §5 사이트맵의 설계가 일치한다. 4단계가 필요한 자리는 *자료실 > 사상체 > 특정 사상체 > 사건 기록 페이지* 정도. SCP의 *평면 URL*은 채택하지 않는다 — 정부 인트라넷 컨셉에 맞지 않는다.

### 3.3. 최종 URL 구조

#### D. 사상체 문서 페이지 (`/archive/entity/aj-06-sp-0341/...`)

> 본 골격의 *메타 박스 항목*과 *본문 섹션*은 `lore/사상체_정의.md` §6.1·§6.2를 진실 출처로 한다. 본 문서는 시각 배치만 결정하며, 항목 정의·필수 여부 등은 진실 출처를 따른다.

**페이지 구조 — 5개 탭으로 분리**:
사상체 문서는 *하나의 페이지*가 아니라 *최대 5개의 별도 페이지*로 구성된다. 각 페이지는 별도 URL을 가지며, 사상체 문서 페이지 상단의 *전용 탭 메뉴*로 전환한다.

| 탭 | URL 패턴 | 내용 | 필수 여부 | 적용 패턴 (v2.0 §10.3.1) |
|---|---|---|---|---|
| 개요 | `/archive/entity/{식별코드}` | 메타 박스 + 개요(§6.1 표 + 설명 H3) + 사상체 이미지 | **필수 토대** | ① 본문형 (메타 박스 강조) |

```
│   ← 필수 토대 2개 + 존재하는 작품 1개만 노출   │
└──────────────────────────────────────────────┘

[ 세 작품 중 둘이 있는 사상체의 경우 (예: 사건 기록만 부재) ]
┌사상체 문서 전용 탭 메뉴 ─────────────────────┐
│ [개요*] [변칙 현상] [대응 지침] [격리 절차]   │
│   ← 필수 토대 2개 + 존재하는 작품 2개만 노출   │
└──────────────────────────────────────────────┘
```

**골격 결정 요점**:
- *5개 탭은 모두 별도 URL의 별도 페이지*. 단일 페이지의 탭 전환(SPA식)이 아니라 *실제 URL 이동*. 빵부스러기·브라우저 뒤로가기·북마크 모두 자연스럽게 동작.
- *전용 탭 메뉴*는 사상체 문서 페이지 안에서만 존재. 상단 메뉴(드롭다운)에는 노출하지 않음.
- *메타 박스*와 *우측 사이드 메타 박스*는 *모든 탭에서 동일하게 노출* — 어느 항목을 보든 사상체의 기본 정보가 항상 시야에 있음.
- *메타 박스*는 본문 폭 전체에 가로로 펼침. 항목은 진실 출처 §6.1의 *개요 표*를 따름.
- 본문 영역은 *2단 그리드* — 좌측 본문 + 우측 세로 사이드 메타 박스. 우측 사이드는 *문서 운용 정보*(작성일·갱신일·작성부서·관련 항목·문서번호)로, 진실 출처에 정의되지 않은 *웹사이트 운영 정보*이므로 본 골격이 추가하는 영역임을 명시.
- *설명*은 §6.1대로 *개요 산하의 H3*이며, *개요 탭*에서만 노출.

#### F. 관문 폼 페이지 (`/login`)

로그인·회원가입이 통합된 단일 URL 페이지. 동일 폼 컨테이너 안에서 *모드 토글*로 두 기능을 전환한다. 상단 메뉴·빵부스러기·접속자 정보 영역 없음 — *인가 전 상태*이므로 사이트 본체 네비게이션 자체가 노출되지 않음.

**모드 전환 동작**:
- 기본 진입 시 *로그인 모드* (인가 확인).
- 폼 하단의 *[회원가입 신청]* 링크 클릭 시 같은 컨테이너 안에서 *회원가입 모드*(인가 신청)로 전환. URL은 그대로 `/login` 유지.
- 회원가입 모드에서 *[로그인]* 링크 클릭 시 로그인 모드로 복귀.
- 모드 전환은 SPA식 컨테이너 내 갱신 — *페이지 새로고침 없음*. 행정 양식의 *건조한 즉시 전환* 톤.

**골격 결정 요점**:
- *단일 URL `/login`*에서 두 모드 운영. `/signup` URL은 두지 않음.
- 로그인 모드는 입력 2칸(식별자·식별번호), 회원가입 모드는 3칸(사용자명·식별자·식별번호).
- 폼 *제목*과 *버튼 라벨*이 모드에 따라 변경. 컨테이너 위치·치수는 *유지*(시각적 점프 최소화).
- placeholder는 입력 칸 안의 희미한 가이드 텍스트로 표시. 입력 시작 시 사라짐.
- 인가 전 상태이므로 상단 메뉴·접속자 정보 영역·전체 사이트맵 푸터 미노출. 헤더와 약식 푸터만.
- 호러 연출은 *거의 0%* (§4 호러 연출 매트릭스). *행정 양식*의 건조한 톤만 유지.

##### 3.5.1. 헤더 우측 보류 항목

다음 항목들은 *별도 논의*를 통해 결정 예정이며 현재는 헤더에서 제외된다. 디자인 가이드/mockup 단계 진입 전 또는 진입 후 별도 논의로 추가 결정한다:

- **검색** — 자료실 영역과 연계되는 전역 검색의 노출 여부·범위
- **사이트맵** — 별도 페이지 / 푸터 앵커 / 모달 중 어느 형태인지
- **FAQ** — 노스포비아 톤과의 적합성을 포함하여 도입 여부
- **글자 크기 조절 (S/M/L)** — 접근성 기능의 도입 여부

#### 상단 메뉴 (4개)
1. 본국 안내 (`/about/`)
2. 직무 편람 (`/duty/`)
3. 자료실 (`/archive/`)
4. 공지 (`/notice/`)

**동작**:
- 클릭 시 해당 카테고리 페이지로 이동.
- 마우스 호버 시 **1차 드롭다운**이 펼쳐짐 — 그 카테고리의 직속 하위 페이지 목록을 보여줌. *그 이상 깊이로는 펼치지 않음* (2차 드롭다운 없음).
- 드롭다운 내용:
  - 본국 안내 호버: 본국 개요 / 연혁 / 조직 구성도 / 지휘 체계 / 본국 시설 / 설립 근거 법령
  - 직무 편람 호버: 사상체 체계 / 인사·권한 체계 / 운영 지침
  - 자료실 호버: 사상체 일람 / 용어집 / 검열 표기 규약
  - 공지 호버: 일반 공지 / 사건 보고 / 인사 공지
- 드롭다운의 각 항목은 클릭 시 해당 서브 카테고리 페이지로 이동.
- *사상체 문서 페이지* 안의 5개 항목(개요·변칙 현상·격리 절차·대응 지침·사건 기록)은 상단 메뉴 드롭다운으로 접근하지 않음. *사상체 일람*에서 개별 사상체 진입 후, 사상체 문서 페이지 안의 *전용 탭 메뉴*로만 접근 (§3.4-D 참조).

- 메인 페이지 외 모든 페이지에 노출
- 클릭 가능한 링크

- 저작권 표시 / 약관 / 개인정보 처리방침
