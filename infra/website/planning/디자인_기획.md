# 노스포비아 웹사이트 디자인 기획

본 문서는 본 사이트의 *시각 디자인 결정*에 대한 단일 진실 출처다. 컬러·폰트·타이포·여백·아이콘·레이아웃·호러 연출의 시각 수단 등 *형상에 관한 결정*을 모은다. *왜 그렇게 설계되었는지*의 기획·전략·기능 결정은 [`웹사이트_기획_확정_v2.0.md`](웹사이트_기획_확정_v2.0.md)가 진실 출처이며 본 문서는 그 위에서 *시각적으로 어떻게 보일지*만 다룬다.

## §0. 본 문서의 사용법

### §0.1. 본 문서의 운영 모델

본 문서는 *완성된 명세*가 아니라 *살아있는 추출 보관소*다.

```
[mockup 페이지 N개 작성]
      ↓
[즉각 피드백 + 시각 결정 확정]
      ↓
[본 문서의 해당 절에 *해당 결정만* 추출 정리]
      ↓
[다음 mockup이 그 결정을 기반으로 작성]
      ↓
[새 결정 누적 → 본 문서가 점진적으로 살이 붙음]
```

처음부터 모든 절이 채워질 필요는 없다. 각 절은 *상태 표기*(`확정`·`진행 중`·`보류`·`mockup 대기`)와 함께 발전한다.

> **⚠ 본 문서의 모든 시각 결정은 *임시 상태*다.** mockup 사이클이 *진행 중*이므로, 추출된 결정은 *다음 mockup에서 변경될 수 있다*. mockup 사이클이 종료되는 시점에 본 문서 전체를 *재논의·정밀 검토*하여 **정식 확정본**(가칭 `디자인_명세_확정.md`)으로 격상한다.
>
> 격상 전까지는 본 문서를 *살아있는 임시 기록*으로 본다. 절별 `상태` 표기를 통해 *어느 부분이 더 굳어졌는지* / *어느 부분이 변경 가능성 높은지* 판단한다.

### §0.2. 진실 출처와의 관계

- 본 문서는 *시각 결정*만 다룬다. 페이지 존재 여부·플로우·기능은 [`웹사이트_기획_확정_v2.0.md`](웹사이트_기획_확정_v2.0.md)가 진실 출처.
- 두 문서가 충돌하면 *기획 확정*이 우선. 본 문서가 그 결정의 시각을 *어떻게 표현할지*를 정리.
- *어떤 페이지가 어떤 레이아웃 골격을 쓰는가*의 구조 결정은 [`사이트구조.md`](사이트구조.md). 본 문서는 그 골격의 *시각 형상*을 명세.
- *현재까지의 mockup 완료 목록*과 *다음 작업 순서*는 [`작업_진행상태.md`](작업_진행상태.md). 본 문서는 mockup의 *시각 결정*만 흡수.

### §0.3. mockup 보관소

모든 mockup HTML은 [`mockup/`](../mockup/) 폴더에 보관된다. 본 문서는 mockup에서 *결정만 추출*하고, mockup HTML 자체는 그 결정을 *실험·검증·시연*하는 자료로 남는다. mockup의 실제 코드를 본 문서가 그대로 옮기지 않는다 — *결정의 표면 형태*만 정리.

### §0.4. LLM 작업 가이드

새 mockup 사이클이 끝나면 다음 절차로 본 문서를 갱신한다:

1. *그 mockup이 굳힌 시각 결정*을 식별한다 (컬러·폰트·여백 수치, CRT 효과 강도, 글로우 토큰 등)
2. *어느 절에 들어가야 하는지* 판단한다 (§1 토큰 / §2 레이어 / §3 페이지별 골격 / §4 공통 / §5 커스터마이즈 / §6 호러 수단 / §7 모바일)
3. 해당 절의 *기존 결정과 충돌이 없는지* 검증한 뒤 추출
4. 본 문서의 `최종 갱신`과 *변경 이력*을 갱신

## §1. 디자인 토큰 (살아있는 결정의 핵심)

본 절은 사이트 전역에서 *공유되는 수치·이름·체계*를 모은다. mockup마다 각자 정해진 값을 쓰지 않도록 *토큰화* 한다. 토큰은 CSS 변수·디자인 시스템 단위로 옮겨지는 결정의 1차 후보다.

### §1.1. 컬러 팔레트

상태: **부분 확정 (임시)** — A 단계 mockup에서 *OS 레이어 그레이* 및 *관리국 시스템 차가운 종이 톤*이 임시 정착. 노스포비아 *남보라 침투*는 사상체 문서 mockup에서 결정 예정.

기획 결정(웹사이트_기획_확정 v2.0 §3):
- *관리국 상징색* = 차가운 그레이 (청록 또는 청색이 옅게 섞인 무채색에 가까운 톤)
- *노스포비아 고유 상징색* = 남보라 `#322659` (사상체 한정, 노스포비아 문서 진입 시 *침투*)
- *포인트 원리*: 관리국 상징색은 *바탕*, 노스포비아 남보라는 *침투*

#### §1.1.1. OS 레이어 컬러 (mockup `access.html`·`login.html`·`desktop.html`에서 임시 정착)

```
--bg              #000000   /* CLI 콘솔 배경 (검은) */
--bg-os           #0a0e12   /* 데스크탑 외곽 (검은+청 한 점) */
--fg              #c8c8c8   /* 본문 그레이 */
--fg-dim          #6a6a6a   /* 보조 텍스트 */
--fg-strong       #ffffff   /* 강조 */
--accent          #e4e4e4   /* CLI 강조 (밝은 그레이) */

/* Win98 위젯 차가운 그레이 */
--w-face          #c8ccd0   /* 다이얼로그·태스크바·시작 메뉴 본체 */
--w-face-light    #e0e4e8   /* 밝은 베벨면 (top·left) */
--w-face-dark     #7a8088   /* 어두운 베벨면 (bottom·right) */
--w-face-darker   #3a4048   /* 가장 어두운 베벨 라인 */
--w-text          #0a0e12   /* 위젯 본문 */
--w-text-dim      #4a5058   /* 위젯 보조 */
--w-title-bg      #1f2d3a   /* 타이틀바 (차가운 어두운 청회) */
--w-title-fg      #ffffff

```

**Win98 바탕화면 자산 (임시 정착)**:

| 항목 | 결정 |
|---|---|
| 자산 파일 경로 | `mockup/assets/desktop-wallpaper-bliss-pixel.png` |
| 자산 명명 규칙 | `{페이지}-{역할}-{내용 식별자}.{확장자}` 형식. 예: `desktop-wallpaper-bliss-pixel.png` |
| 이미지 형식 | PNG (사용자 제공 픽셀 아트, 이미 픽셀화된 자산) |
| `background-size` | `cover` + `background-position: center center` |
| `image-rendering` | `pixelated` (브라우저의 픽셀 보간 차단 — 옛 픽셀 자산 보존) |
| `filter: saturate(0.82)` | 옛 CRT 모니터의 *살짝 색이 빠진 톤* 재현. 위젯·다이얼로그는 별도 레이어라 영향 없음 |
| 채도 조정 보류 범위 | 0.75 (더 빠짐) ~ 0.90 (덜 빠짐). 현재 0.82가 정착 |

> 본 자산은 *교체 가능 외부 파일*. 향후 *APMB 전용 픽셀 아이콘 자산 작업*과 함께 *대체 바탕화면 자산*도 신설 가능.

시스템 색 (모든 레이어 공유):
```
--ok-tag    #88c878   /* 녹색 — [ OK ] 태그·확인 */
--warn      #d8c87a   /* 노란빛 — [WARN] 태그 */
--crit      #d88a7a   /* 붉은빛 — [ ERR ]·접근 거부·긴급 */
```

#### §1.1.4. 라이트모드/다크모드 처리

본 사이트는 *모든 레이어가 고정 톤*이라 별도 라이트/다크 토글이 없다. *OS 레이어 = 어두움*, *관리국 시스템 레이어 = 차가운 밝은 종이 톤*으로 자연 분리됨.

### §1.2. 폰트와 타이포그래피

상태: **부분 확정** — OS 레이어용 모노스페이스 체인은 mockup에서 확정됨. 관리국 시스템·문서 레이어용 본문 폰트는 mockup 대기.

#### §1.2.1. 모노스페이스 폰트 체인 (OS 레이어)

`access.html`·`login.html`에서 확정:
```
font-family: 'Cascadia Code', 'JetBrains Mono', 'Fira Code', 'Source Code Pro',
             'D2Coding', 'Menlo', 'Consolas', 'Courier New', monospace;
```

선정 원리:
- *박스 드로잉 문자(`█ ╗ ═` 등)의 균등 폭 렌더링*을 보장
- 한글 폴백(`D2Coding`) 포함
- 윈도우(`Cascadia Code`)·맥(`Menlo`)·일반(`Consolas`) 환경 모두 커버

#### §1.2.2. 본문 폰트 (관리국 시스템·문서 레이어) — 임시 정착

상태: **부분 확정 (임시)** — `oath.html`·`dashboard.html`에서 정착.

```
font-family: 'Pretendard', 'Apple SD Gothic Neo', 'Malgun Gothic', 'Noto Sans KR',
             'MS Sans Serif', 'Tahoma', sans-serif;
```

선정 원리:

#### §2.1.1. CLI 인트로 (`mockup/access.html`) — 굳어진 시각 결정

- 검은 배경 위에서 *부팅 시퀀스 로그*가 자동으로 흐르는 형식
- **CRT 효과 5종** (전 OS 레이어 공유):
  - *스캔라인* — 2px 간격 가로 줄무늬, 4% 흰색
  - *노이즈 텍스처* — SVG `feTurbulence`, 0.42s steps(3) 애니메이션, 55% opacity
  - *비네팅* — 라디얼 그래디언트, 가장자리 45% 어두움
  - *스캔 빔* — 120px 높이 미세 발광 띠, 7s linear 위→아래 흐름
  - *CRT 깜빡임* — 4~5s 주기로 잠시 91~96% 어두워짐
- **텍스트 발광**: `text-shadow: 0 0 1px rgba(220, 220, 220, 0.55)` 미세 인광
- **부팅 로그 5단 페이즈**: BIOS/OS → 보안·네트워크 → 인트라넷 접속+가상어휘 → 세션동기화 → IG 게이트. 약 160줄, 11초
- **로그 색상 단계**: `ok`(본문 그레이) / `info`(흐린 그레이) / `warn`(노란빛) / `crit`(붉은빛) / `label`(강조 그레이)
- **로그 태그 색상**: `[ OK ]`(녹색) / `[INFO]`(흐린 그레이) / `[WARN]`(노란빛) / `[ ERR ]`(붉은빛)
- **호러 균열 (랜덤 8%)**: 발동 시 0.7s 화면 흔들림 + 밝기·반전 필터 + 스캔라인 플래시 오버레이. 평소엔 발생 안 함
- **노스포비아 흔적**: `[WARN] Cell Aj-06-SP-0341 :: anomalous signal (within tolerance, t=+47s)` — 160줄 중 한 줄로 빠르게 흐름. *정보 과부하* 미감
- **언어**: 로그 본문 전부 영문. 한글은 mockup 검토용 컨트롤(우하단 버튼)에만 존재
- **로그 흐름 방식**: 가득 차면 `translateY`로 위쪽이 잘려 올라감 (실 부팅 화면 톤)

#### §2.1.2. CLI 로그인 (`mockup/login.html`) — 굳어진 시각 결정

- CLI 인트로와 동일한 CRT 효과 5종 + 폰트 체인 + 텍스트 발광
- **흐름**: 짧은 접속 성공 로그 4줄(영문) → APMB 진입 패널 → 안내 페이즈(한글) → CLI 프롬프트
- **APMB 진입 패널 구성**:
  - 위·아래 78자 분할선 (`─`)
  - 7행 ASCII 배너 (`#` 단일 문자, 안정 렌더링 보장)
  - 배너 글로우: `text-shadow: 0 0 2px + 0 0 6px + 0 0 14px` 3단 발광
  - 메타 데이터 3행 (System / Operated by / Gate) — 좌측 정렬, 라벨 폭 14ch
  - `— CLASSIFIED · GOVERNMENT USE ONLY —` 분류 라벨 (12px, letter-spacing 1.5px)
- **CLI 프롬프트 형식**: `IG@10.42.7.187:~$ [단계 라벨 > ] _`
  - `IG` (흰색 강조) `@` (회색) `10.42.7.187` (본문 색) `:~` (회색) `$` (그레이 강조)
  - 시청자의 실제 IP가 아니라 *APMB 게이트웨이가 IG 세션에 부여한 가상 주소*
- **단계 라벨**: `선택 > ` / `식별자  입력 > ` / `식별번호 입력 > ` / `사용자명 입력 > `
- **CLI 명령 시스템**: `/`로 시작하는 입력은 명령. `/help`·`/login`·`/signup`·`/whoami`·`/clear`·`/exit`(거부). 잘못된 명령은 `[ ERR ] unknown command: /xxx` + 도움말 안내
- **단계 전환 흐름**: 안내 → 1/2 선택 → 식별자·식별번호(·사용자명) 입력 → 검증 로그 → 다음 페이지 안내. 페이지 새로고침 없이 CLI 로그가 계속 이어짐

**창 시각 구조**:
- 제목바 (26px 어두운 차가운 그레이 그라데이션 `#1f2730` → `#2c333b`)
  - 좌측 16×16 픽셀 아이콘 + 제목 텍스트 `관리국 시스템 — APMB Intranet (v6.0.3)`

**창 동작**:
- 드래그: 제목바 잡고 이동
- 리사이즈: 핸들 드래그 (최소 1024×768 보장)
- 최대화 (`□`): 데스크탑 영역(태스크바 위까지) 전체로 확장 ↔ 이전 크기 복귀 토글

- 닫기 (`×`): 창 제거 (다음 더블클릭 시 다시 열림)

**창 내부 콘텐츠**:
- iframe으로 다른 mockup 페이지 로드 (`oath.html` / `dashboard.html` / `login.html`)
- iframe 자체 viewport가 *창 크기 기준*으로 동작 — 창을 줄이면 콘텐츠가 자동으로 모바일 레이아웃으로 전환 (단 PC 최소 1024px 하한이라 모바일 전환은 mockup에선 *시연 불가*)
- *mockup 전용 페이지 선택 바* (실배포 시 제거): 본문 위에 *어느 페이지를 iframe으로 표시할지* 선택. 우측에 *현재 창 크기 실시간 표시* (`1100 × 760`)

## §5. 공용 문서 레이아웃 적용 패턴과 사상체 문서 시스템

본 절은 [`웹사이트_기획_확정_v2.0.md`](웹사이트_기획_확정_v2.0.md) §10의 3계층 분류를 *시각 결정* 측면에서 구체화한다.

### §5.0. 3계층 분류 (시각 결정의 정렬 축)

```
[1계층] 공용 문서 레이아웃 — 기본형 (강제 아님, 응용 가능)
```

각 계층의 *시각 결정*은 별도 절로 분리:
- 1계층 기본 시각 — §1 (토큰), §2.3 (문서 레이어), §3.3 (C 골격 = 공용 문서 본체)
- 2계층 적용 패턴 — §5.1
- 3계층 사상체 문서 — §5.2 + §3.4 (D 골격)

기존 검토 단계에서 *표·매트릭스형*이 별도 패턴으로 등장했으나, v2.0 §10.2에서 *폐기*됨:

#### §5.2.1. 5탭 메뉴 시스템 시각

상태: **mockup 대기** — 노스포비아 개요 탭 mockup에서 정착.

상태: **mockup 대기** — 노스포비아 사상체 문서가 *남보라 침투* 첫 적용 사례.

**적용 정책** (v2.0 §10.3.3과 정합):
- 모든 사상체 문서에 적용되는 것이 *아님*
- 사상체의 콘셉이 강할 때에 한정. 사상체마다 *적용 여부 결정*
- 적용 시 *해당 사상체의 5탭 모두에 일관 적용*
- 사상체 문서를 벗어나면 *공용 톤으로 복귀*

**변형 가능 시각 토큰 (정의 예정)**:
- *배경 톤* — 관리국 그레이에 콘셉 컬러 옅게 침투
- *노이즈 강도* — 일반은 미세, 콘셉 사상체는 강해질 수 있음
- *레이아웃 비율* — 메타 박스 확장 / 사이드 축소 / 본문 강조
- *글로우 강도* — 일반은 거의 없음, 콘셉 사상체는 본문·헤더에 미세 발광
- *분리선·테두리 스타일* — 콘셉에 맞는 변형
- *호러 연출 강도* — 기본 *중간* ± 사상체별 조절 (v2.0 §6 정합)

#### §5.2.4. 노스포비아 — 남보라 침투 (첫 적용 사례)

상태: **mockup 대기**.

기획 결정(v2.0 §3): *관리국 톤에 남보라가 물듦*. 이 대비가 시각적으로 선명해야 한다.

구체 시각 결정 후보 (mockup에서 확정):
- 헤더의 *제목 영역*에만 남보라 한 줄 라인
- *전체 배경*에 남보라가 옅게 깔림
- *메타 박스의 식별 코드*만 남보라
- *사이드 메타의 사상체 본질 키워드*에 남보라

침투 강도는 *너무 강하지 않게* — 5탭 중 *변칙 현상*·*사건 기록* 탭에서 강해질 수 있고, *개요* 탭은 절제.

- 로그 줄바꿈 허용 (`pre` → `pre-wrap` + `word-break: break-all`)
- **부팅 로그**: PC 약 160줄 11초 → 모바일 28줄 약 3.4초 (1/3 단축판)
- 5단 페이즈 구조 보존 + 노스 흔적 1줄 유지
- 호스트명 `SC-T2-M (mobile)`로 *모바일 접속 경로* 명시

### §7.2. 모바일 로그인 — CLI 모바일 레이아웃 (login.html 정착)

- PC와 동일한 CLI 콘솔 톤 유지
- **APMB ASCII 배너 — 4행 22문자 압축판** (`apmbBannerMobile`)
- ASCII 분할선(`─` 78자) → *시각 분할선*(`border-top: 1px solid`)으로 교체
- 패널 메타 — *라벨/값 별도 줄*로 분리, 라벨은 대문자 letter-spacing
- **CLI 프롬프트** — 한 줄 → *주소 / 단계+입력* **2줄로 자동 분리** (`.prompt-row { flex-wrap: wrap }` + `.prompt-addr { width: 100% }`)
- 입력 영역 `min-width: 120px` + `flex: 1 1 120px` 보장
- 모드 힌트 — 좌우 폭 확장, 글자 작게

### §7.3. 모바일 보안 서약서 (oath.html 정착)

- 폰트 14px → 13px, *줄 간격 1.7* (정독 가독성 우선)
- 문서 본체 `max-width: 100%`, 그림자 축소
- 메타 4행 — 가로 2칼럼 → *세로 적층 (라벨/값)*
- 본문 패딩 축소, 정독 친화적 크기
- 동의 영역 — *체크박스 18×18px* (터치 타겟), 버튼 *세로 적층 + 풀폭 40px 높이*

### §7.4. 모바일 메인 대시보드 (dashboard.html 정착)

- 헤더 — *브랜드+검색 세로 적층* (`flex-direction: column`)
- 상단 메뉴 — *가로 스크롤* (`overflow-x: auto`), 드롭다운 비활성 (모바일은 호버가 없음 → 메뉴 클릭 시 카테고리 페이지로 직진)
- 접속자 정보 — `flex-wrap: wrap`, 구분점(`·`) 숨김
- 최근 사건 + 업데이트 *2단 → 1단*
- 리스트 항목 — *제목이 한 줄을 차지*, 태그·날짜는 상단
- **문서 흐름 표 → 카드 리스트로 전환** (`display: block` + `::before`로 *조회 / 반응* 라벨 인라인 추가)
- 카테고리 카드 *4열 → 2열*
- 푸터 — 3컬럼 → 세로 적층

### §7.5. 공통 적용 사항

- 모든 페이지에 `<meta name="viewport" content="width=device-width, initial-scale=1">` 추가
- 미디어 쿼리 표준: `@media (max-width: 1023.98px) { ... }`
- 모바일 본문 폰트 베이스 12~13px (페이지 성격에 따라)
